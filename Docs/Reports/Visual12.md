## 1. A. 궤도석 궤도 (24 §24.5)

### 1.1 원인 확인

`A_moving_before_*`(예전 꼬리)에서 확인했다. 중력원이 움직이면 `TrailRenderer`가 월드에 쌓은 점들이 뒤로 끌려 궤도석마다 긴 직선 꼬리가 생긴다. 궤도가 찌그러진 나선처럼 보인다.

**한 틱 늦음은 없었다.** 중력 고리(`CursorView`)도 보간된 위치가 아니라 `root.GravityWorld`(마지막 고정 틱 위치)에 그린다. 궤도석의 `center`도 같은 틱의 같은 값이었다. 그래도 그리는 중심은 이제 렌더 시점의 `GravityWorld`를 직접 읽는다. 고리와 한 점에서 갈라질 수 없게 하기 위해서다. 중력 고리를 프레임 보간하는 것은 이번 범위가 아니라서 하지 않았다.

### 1.2 만든 것

- **꼬리 = 궤도 호.** 매 프레임 지금 중심을 기준으로, 같은 타원 위에서 궤도석이 `trailSec`(0.8초) 동안 지나온 구간을 계산해 `LineRenderer`로 그린다. 시간을 거꾸로 밟으며 같은 등면적 속도(중점법)를 쓰므로, 멈춰 있을 때의 길이는 예전 꼬리와 같다. 세차(15°/초)도 같이 되돌린다.
- 폭(`trailWidthPx`), 색, 끝으로 갈수록 투명해지는 것, 폭이 줄어드는 곡선, 연출 강도 처리는 예전 꼬리와 같다.
- 홀드를 시작하면 호가 0에서 `trailSec`까지 자란다. 예전 꼬리가 처음에 비어 있다가 자라던 것과 같다.
- `AbilityTable.satellite.trailInOrbitFrame` (켬). 끄면 예전 월드 꼬리. 콘솔 `[Visual] orbit stone ribbon: …`.
- **바꾸지 않은 것:** 궤도 모양, 끌어당김·견인, 범위 안에서 놓기, 결정 버프 중 궤도가 커지는 것(`unit`이 버프 반경을 따른다. `E5_buff_A_satellites`).

캡처: `A_moving_before_1000/1500ms` ↔ `A_moving_after_1000/1500ms`, `A_still_before/after_2000ms`, 버프 중 `E5_buff_A_satellites`.

## 2. B. 렌즈 칸 4개 (26 §12.2)

### 2.1 구조

- `Lens.hlsl`: 전역 렌즈 한 칸(`_BHLens`)을 **4칸 배열**(`_LensA[4]`, `_LensB[4]`)로 바꿨다. 0 블랙홀, 1 중력원, 2 수축 파동, 3 묶음 일렁임. 칸마다 중심, 반지름, 밀기 세기, 도달 거리, 회전, 띠 폭, 모양(구멍 / 부풂 / 고리 띠)이 있다.
- `Dust`, `DustTrail`(정점을 앞으로 옮김)과 `Starfield`(픽셀마다 거꾸로 찾음)가 네 칸을 순서대로 적용한다. 셰이더 파일은 그대로 두고 `Lens.hlsl`만 바꿨다. 화면 복사 없음. Camera Sorting Layer Texture 안 켬.
- `LensSlots.cs`: 칸 주인들(블랙홀, `VisualFx`)이 프레임마다 값을 넣으면 `beginContextRendering`에서 한 번에 전역 배열로 넘긴다. 실행 순서를 타지 않는다.
- 블랙홀의 빛 고리와 원판 비우기(24 §24.3)는 0번 칸 전용 값 `_BHLensShape`으로 그대로 남겼다. 블랙홀 그림은 10·11차와 같다.

### 2.2 항목

| 항목 | 기본 | 만든 것 |
|---|---|---|
| **D1 중력원 렌즈** | 켬 | 홀드 중 중력원 둘레를 **부풂** 모양으로 밀어낸다. 중심과 가장자리(중력 반지름 × 0.8)에서 0이고 1/3 지점이 가장 세다. 원판 지우기 없음. 세기 = 0.2 × 게이지(모은 질량 / 다음 임계값) × (1 + 링 × 0.05). 값은 "도달 거리의 몇 배를 미는가"다. 놓으면 0.3초에 선형으로 풀린다. 홀드 중에 천체가 완성돼 게이지가 0이 되면 0.15초에 걸쳐 내려간다(뚝 끊기지 않게) |
| **D3 블랙홀 소용돌이** | 켬 | 블랙홀 칸에 회전을 더했다. 가장자리 안 40°, 도달 거리에서 0°, (1 − 거리)² 곡선. 반시계 방향이다(먼지 소용돌이와 같다). 밀기와 같은 램프로 들어오고 나간다. `AbilityTable.blackHole.lensTwistDeg` |
| **D2 수축 파동 일렁임** | 끔 | 수축 고리 반지름 자리에 가우스 띠(폭 0.15 × 반지름)를 둔다. 세기 0.15 × 띠 폭만큼 밖으로 민다. 고리가 사라질 때 같이 옅어진다 |
| **D4 ×N 묶음 일렁임** | 끔 | 묶음 자리에서 0.4초 동안 420px(× 월드 배율)까지 퍼지는 띠(폭 0.25 × 반지름). 세기 0.2 × ln N, 퍼지며 옅어진다 |

전부 연출 강도를 곱한다. 강도 0이면 네 칸이 모두 0이다.

캡처: `D1_mass0 / D1_mass_half / D1_mass_full / D1_off_full`(링 7, 중력원 화면 가운데 고정), `D3_open1s_on / D3_open1s_off`, `D2_implode_ripple_on / off`, `D4_bundle_ripple_x12`.

## 3. 확인 방법 (키)

| 키 | 하는 일 |
|---|---|
| `B` | 배경 보강(B1a, B2, B3, B4) 전부 켬 ↔ 끔 |
| `N` | 왜곡: 지금(D1, D3) → + D2·D4 → 전부 끔 → 지금 … |
| `J` | 이펙트: 지금(E2, E4, E5) → + E1 → 전부 끔 → 지금 … |

- 토스트와 콘솔 `[Visual] …` 한 줄. 런타임만 바뀌고 저장되지 않는다. 다시 켜면 데이터 값으로 시작한다.
- `N`·`J`의 첫 단계 "지금"은 데이터 플래그가 아니라 기본 조합(찬성 항목만 켬)이다.
- 항목 하나씩 끄려면 아래 값 표의 플래그를 인스펙터에서 끈다. 실행 중에 바꾸면 **다음 플레이**에 반영된다(플래그는 시작할 때 읽는다). 세기·시간 값은 **즉시** 반영된다.
- 블랙홀·수축·궤도석은 숫자 키로 강제한다: `5` 블랙홀, `2` 수축, `3` 궤도석, `6` 전부.
- **F11 연출 강도 0**이면 렌즈, 시차, 성운 소용돌이, 팝 움직임, 고리 맥동, 버프 테두리, 흔들림, 히트스톱이 모두 꺼진다. ×N 숫자 자체는 보인다.

## 5. D. 이펙트 (26 §12.3)

| 항목 | 기본 | 만든 것 |

### 5.1 E3 새 티어 첫 완성 카드 (시안만)

- `E3_mock_A_card`: 테두리가 금빛인 어두운 카드
- `E3_mock_B_text`: 카드 없이 글자만. 뒤에 흐린 어둠을 깔았다

설명 문장("별이 되기엔 조금 모자란, 스스로 희미하게 빛나는 천체")은 시안용으로 지은 것이다.

## 8. 스펙과 다르게 하거나 정한 것

1. **A "한 틱 늦다"**: 실제로는 고리와 궤도석이 같은 틱 위치를 쓰고 있었다(§1.1). 새 보간은 넣지 않고 같은 값을 렌더 시점에 읽게만 했다.
2. **A 호 길이**: 세차까지 되돌려서 멈춰 있을 때 예전 꼬리와 같은 모양이다. 홀드 시작에서는 호가 0부터 자란다.
3. **D1 모양**: "중력원 둘레를 살짝 바깥으로"를 가운데와 가장자리가 0인 부풂으로 만들었다. 가운데(형성 중 천체 자리)는 움직이지 않는다. 세기 0.2는 "도달 거리 대비 최대 밀기"로 읽었다. "링"은 해금 최고 티어(링 번호)다.
4. **D2·D4 세기 단위**: 띠 폭 대비 밀기 비율. D4의 log 계수는 0.2 × ln N, 퍼지는 거리 420px는 정해서 넣었다.
5. **B2 단위**: "화면 끝에 있을 때 화면 크기의 몇 배"로 읽었다. 시차와 성운 소용돌이도 움직임이라 연출 강도를 곱한다.
6. **B3**: 런 화면만이 아니라 모든 화면(결과·트리 포함)에 보인다(배경이 하나라서). 종류 순서는 링 번호에서 나오므로 같은 링이면 늘 같은 천체다.
7. **E2**: 묶음뿐 아니라 놓을 때의 ×N 라벨도 팝·색·합치기를 탄다(같은 라벨 함수).
8. **E4**: 고리를 키울 때 같은 오브젝트에 달린 능력 충전 호도 0.2초 같이 커진다.
9. **E1 새 티어 첫 완성**: "이번 판을 시작할 때의 최고 티어보다 높은 천체"로 판정한다. 한 판에서 두 단계를 처음 만들면 두 번 걸린다.
10. **`N`·`J` 순환**은 데이터 플래그가 아니라 정해진 조합으로 간다(§3).

## 9. 알려진 문제

- **시작할 때 에디터가 플레이 모드였다.** 개발자의 플레이였을 수 있다. 첫 컴파일이 그 플레이 중에 일어나 `UIButton`/`GameRoot`의 NullReference가 쏟아졌고, 플레이를 멈췄다. 세이브 파일 시각(15:19)은 백업 전후로 같았다.
- **B1a가 거의 안 보인다.** 0.0225는 캡처에서 눈으로 구분하기 어렵다. B4 성운 소용돌이도 그만큼 약하게 보인다. 원하면 `backdropNebulaStrength`를 0.4~0.5로 올려 본다. B1b 시안의 0.045가 참고다.
- **D1은 링 7 캡처에서 미묘하다.** 가득일 때 고리 안쪽 먼지가 바깥으로 조금 비켜난 정도다. "약하게 시작"이라 그대로 두었다. 더 보이게 하려면 `gravityLensStrength` 0.3~0.4.
- **D2·D4도 약하다.** 띠가 얇고 짧아서 정지 캡처에서는 잘 안 보인다. 움직이는 화면에서 판단하는 것을 권한다.
- **B3 거대 행성**은 고리가 행성 중심 기준 타원이라 화면에는 호 몇 줄로만 걸린다. 16:9 기준으로 자리를 잡았다. 다른 비율에서는 구석 위치를 다시 봐야 할 수 있다.
- **F1 캡처는 가벼운 장면이다.** 장면을 다시 만든 직후라 먼지가 474개뿐이었다. 빌드 성능은 재지 않았다(프롬프트대로). 렌즈 4칸은 별 배경에서 픽셀당 최대 4번, 먼지 정점당 4번 계산이 늘었다. 꺼진 칸은 바로 건너뛴다. 다음 빌드 확인 때 `-perfbench`로 보는 것을 권한다.
- 처음 시도한 F1 캡처에서 링 11 홀드가 청색 거성을 만들어 엔딩이 돌았다(테스트용 상태에서). 세이브는 되돌렸다. 엔딩을 이미 본 상태로 다시 찍었다.
- `Docs/17_Playtest_Guide.md`의 디버그 키 표에 `B`/`N`/`J`를 넣지 않았다(기획 문서라서). 기획 세션 몫이다.
