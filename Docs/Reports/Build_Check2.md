## 3. 성능 비교

**같은 날(10/14) 같은 기계에서 세 빌드를 두 번씩** 쟀다 (7주차 → 5차 → 새 빌드, 그다음 새 빌드 → 5차 → 7주차). 표의 칸은 `평균 / 99퍼센타일 fps`, `1회 · 2회`. 1920×1080, vSync 0, 예열 2초 / 표본 6초, `-perfbench`.

**처음 잰 7주차 빌드는 전 장면이 정확히 60.0fps였다.** 노트북이 배터리 전원이었다(어댑터 분리, 72%). 먼지 틱도 1차의 3배였다(8,000에서 3.13ms). 개발자가 어댑터를 꽂은 뒤 1분 기다렸다가 세 빌드를 처음부터 다시 쟀다. 배터리 측정은 `battery_perf_week7build_1014.md`로 따로 남겼다 (§6-1).

최적화는 하지 않았다(프롬프트 지시). 늘어난 것만 적는다.

1. **능력 없는 먼지 8,000 장면: 먼지 틱 +0.45ms(약 +40%), 메시 재구성 +0.55ms(약 +18%).** 궤적 메시와 나머지는 그대로다. 평균 −12%, 99퍼센타일 −20% 안팎(5차 빌드 2회 117.1 / 84.4 대비 104.0 / 69.1). 이 장면은 능력 노드를 빼고 화면 밖 먼지도 0이다. 그래도 바뀐 것은 6~8차의 먼지 쪽 변경이다: **중력 반경 축소**(`gravityGrowthScale` 0.7, 결정 배수) — 반경이 작으면 잡히지 않고 들떠 움직이는 먼지가 늘어 메시·힘 계산이 커진다, **먼지 보충 가속**(`dustRefillBoost` 3) — 틱마다 다시 만드는 먼지가 늘어난다, 능력 시스템의 틱마다 하는 일(결정 `Amplify`, 강제 상태 확인). 어느 하나가 얼마인지는 나누어 재지 않았다. 밸런스 패스에서 반경과 보충을 다시 정할 때 같이 재면 된다.
2. **능력 트리대로 장면: 먼지 틱 +1.0ms, 메시 +0.7ms.** 링 11 트리가 주는 능력이 5차(셋)보다 늘었다(증폭 결정, 진화 노드). 최대 프레임 27.7ms가 두 번 다 나왔다(5차 17.7~19.9). 99퍼센타일은 62.7 · 71.3으로 목표 위다.
3. **최악 장면(블랙홀 + 즉시 보충)은 5차와 거의 같다.** 먼지 틱 4.2~4.8ms, 메시 4.2~4.3ms. 블랙홀이 열리면 전역 인력이 다른 능력보다 압도적으로 비싸고, 그 위에 결정·진화가 더해진 몫은 측정 흔들림 안이다. 99퍼센타일이 두 빌드 모두 50 경계에 있는 것은 오늘 기계가 1차(10/7, 같은 5차 빌드 85.5 / 62.6)보다 느리기 때문이다(같은 5차 빌드의 이 장면 평균이 1차 85.5에서 오늘 81.1 · 69.8). 이 장면은 틱마다 상한까지 다시 채우는 합성 최악이고, 실제 블랙홀은 화면을 비우며 가벼워진다(1차 251.7 / 96.4).
4. **결과·트리 화면은 늘지 않았다.** 새 빌드 결과 377.6 · 372.0, 트리 315.8 · 296.6 (7주차 빌드 373.4 · 362.1 / 379.2 · 378.1). 트리가 7주차보다 15~20% 느린 것은 1차에서 본 TMP 글자와 곡선 연결 비용 그대로다.

## 6. 알려진 문제와 메모

1. **배터리 전원에서는 빌드가 60fps에 묶인다.** 같은 7주차 빌드가 어댑터를 꽂자 111~115fps로 풀렸다. 먼지 틱도 배터리에서 2.4~2.7배 느리다. 7주차 보고의 "60fps 고정"(`com.unity.ai.assistant`)과 증상이 같아 헷갈리기 쉽다. **성능은 어댑터를 꽂고 잰다.** 개발자가 노트북 배터리로 플레이하면 60fps가 정상이다.
2. **최악 합성 장면의 99퍼센타일이 50 경계**(49.9 · 56.6, 5차 빌드도 50.3 · 50.6). 기계 상태에 따라 넘나든다. 밸런스 패스에서 먼지 상한이나 보충을 올리면 이 장면부터 확인해야 한다.
3. **진화 노드 툴팁의 설명 줄이 패널 오른쪽 테두리 밖으로 조금 넘친다** (`b2_18`: "…두 겹까지 쌓인다"의 끝, 블랙홀 노드 "…화면 전체를 빨아들인다"도 같다). 에디터에서 같은지는 보지 않았다. 고치지 않았다(출시 기능 단계의 UI 정리 거리).
4. 공명 캡처는 2중첩 순간을 찍지 못했다. 스크립트가 흡수를 플레이어 로그로 확인했는데, 로그 파일이 몇 초 늦게 써져 캡처가 2중첩(×1.7, 487 px)이 끝난 뒤 다시 먹은 1중첩에 찍혔다. 2중첩 자체는 로그로 확인했다.
5. 커서 이동은 **테두리 없는 창**에서 확인했다. 독점 전체화면에서 런을 시작하는 경로는 실입력으로 보지 않았다(성능 측정은 독점 전체화면이지만 입력을 넣지 않는다). 기본 실행이 어느 모드인지는 출시 기능 단계의 옵션 화면에서 정해진다.
6. 개발자 세이브의 트리 상태: 링 11이지만 능력 노드는 수축 Lv3, 위성 Lv0만 산 상태였다(로그 `crystal (locked) … blackhole (locked)`). 화면 확인은 디버그 강제로 했으므로 지장이 없다.
7. 캡처에 Windows 정품 인증 워터마크가 보인다(오른쪽 아래). 게임과 무관하다.
8. 실입력 드라이버와 결정 찾기 스크립트는 스크래치패드에만 있다(저장소에 넣지 않음). 결정은 화면에서 금색 덩어리를 찾아 커서를 옮겼고, 홀드 중 형성 천체의 금빛과 헷갈리지 않게 홀드 전에 찾았다.
