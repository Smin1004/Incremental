- 전체화면 모드가 `ExclusiveFullScreen`이 아니라 `FullScreenWindow`로 잡힌 측정이 섞여 있다(코드는 독점을 요청한다). 상한 60에 묶이지 않았으므로(100~300fps) 결과에는 영향이 없었다.

## 5. 고친 것

- **블랙홀 외형이 중간에 청색 거성으로 바뀌는 문제** (빌드 캡처에서 발견). 블랙홀이 열린 동안 들고 있는 질량이 다음 티어를 넘으면 `CursorView`가 티어의 외형을 다시 입혔다. 오버라이드가 있는 동안은 티어 외형을 건너뛰게 했다 (`CursorView.cs` 한 분기). 수정 뒤 빌드를 다시 만들어 `build_08_blackhole_open.png`를 다시 찍었다.
- **`PerfBench`**: 7주차 장면은 능력 노드와 화면 밖 먼지를 빼서 7주차와 같은 장면으로, 새 장면 둘(능력 트리대로 / 전부 최대 + 블랙홀 열림 + 먼지 보충)을 뒤에 더했다. 측정 하네스이지 게임 코드는 아니다.
- 빌드 자체는 고칠 것이 없었다. 패키지 5개 제거, TextMeshPro 전환과 실행 중 Pretendard SDF 폰트 생성, 능력·화면 밖 먼지·과노출 억제 — 전부 빌드에서 그대로 동작했다.

## 6. 알려진 문제와 메모

- **시작 직후 한 번 멈칫**(89~104ms 프레임, §3). 원인을 특정하지는 않았다. 폰트 아틀라스를 미리 채우거나 셰이더를 예열하면 없앨 수 있을 것.
- **블랙홀 성능 장면은 합성**이다(먼지 즉시 보충). 실제 플레이의 블랙홀은 화면을 비우며 가벼워진다 (251.7 / 96.4).
- **개발자 세이브**: 측정과 빌드 실행이 `save.json`·`run_log.csv`를 덮어쓴다(perfbench는 링 11 상태를 만들고 런을 돌린다). 작업 전 `build_check1\dev_before_20261007_173410\`에 복사해 두었고, 끝난 뒤 4파일(`save.json`, `save.bak`, `run_log.csv`, `settings.json`)을 되돌려 `cmp`로 같음을 확인했다. 작업 중 상태도 `build_check1\after_work_*`에 남겼다. 빌드 실행 동안은 `settings.json`의 `pauseOnFocusLoss`를 끈 사본을 썼다(원본 복구됨).
- 빌드 화면 확인의 `build_07`/`build_09`/`build_10`은 측정이 지나간 세이브 상태(능력 노드 없음, 엔딩 미시청)라 트리 능력이 없고 엔딩이 돌았다. 화면 자체의 확인에는 지장이 없다.
- 실입력 드라이버: Unity Input System은 raw input의 **스캔 코드**로 키를 판별한다. `SendInput`에 가상 키만 넣으면 빌드가 무시한다(처음 7장이 전부 결과 화면이었던 이유). 스캔 코드(`MapVirtualKey`)를 같이 넣어야 한다. 스크립트는 스크래치패드에만 있다.
