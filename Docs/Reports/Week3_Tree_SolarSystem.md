# 3주차 보고: 스킬트리 화면(12 §9)과 결과 화면 태양계(13)

| 항목 | 값 |
|---|---|
| 상태 | 12 §9 트리 화면, 13 전체 버전(셰이더 제외) 구현. EditMode 테스트 120개 통과 |
| 작성 | 2026-09-18, 구현 세션 |
| 브랜치 | `skilltree-model` (1단계 보고: [SkillTree_Step1.md](SkillTree_Step1.md)) |
| 환경 | Unity 6000.0.66f2 에디터, 1920×1080. 동작 확인은 가상 키보드·마우스 입력으로 했다 |

## 1. 만든 것

**흐름**: 런 종료 → 결과 화면(태양계) → Space 또는 [스킬트리] → 트리 → Space 또는 [다음 런] → 다음 런. 기존 2단 목록 화면은 지웠다. 런 중이 아니면 먼지와 런 HUD를 숨긴다.

**트리 화면 (12 §9)**
- 링 위 극좌표 배치(반지름 = `treeRingR0Px + minTier × treeRingStepPx`), 선행 노드와 선, 링 원(연 링은 밝게, 다음 링은 흐리게, 그 너머는 숨김).
- 노드 상태별 표시: 잠김(흐린 점), 구매 가능(재화가 되면 맥동, 모자라면 비용 붉게), 보유(`1/2`), 완료(가장 밝게, 이어진 선이 빛남). 관문은 크고 티어 색.
- 클릭 1레벨 구매, 누르고 있으면 0.35초 뒤부터 0.08초마다 연속 구매, 드래그 이동(노드에서 시작해도 구매하지 않고 이동), 휠 확대, 호버 툴팁(관문은 "티어 5 · 판매가 · 필요 질량"). 구매 시 빛 번짐(`effectIntensity` 곱).
- 열 때 구매 가능 노드들의 중심으로 이동하고, 한 화면에 안 들어오면 자동 축소(스펙에 없는 추가).

**결과 화면 태양계 (13)**
- 왼쪽 패널: 수입 카운트업(1.2초), 지난 런 대비, 티어별 개수, 최고 기록, [스킬트리] 버튼. 클릭하면 등장 연출 생략.
- 궤도: 해금 티어 1~8마다 하나(`r0 110`, `step 52`), 이번 런에 행성이 있으면 진하게. 반시계 공전, `ω = 40° × (r0 / r)^1.5`.
- 행성: 이번 런 것만, 크기 `sizePx × 0.5`, 중심 항성 반대쪽이 어두운 초승달 명암. 티어 1~3은 16개 초과 시 소행성대(점 최대 240개, ±8px, 2~4px) + `×N`, 티어 4~8은 12개 + `×N`.
- 항성(티어 9~11): 궤도가 아니라 하늘에 밝은 점으로(런당 최대 20개).
- 중심 항성: 원시성(주황, 느린 맥동) → 적색 왜성 → 태양형 → 청색 거성(`highestTierCreated` 기준). 처음 항성을 만든 런에서 점화 섬광.
- 등장: 행성이 소실점(우상단)에서 날아와 궤도에 안착, 낮은 티어부터, 1.2초.

**런 중 퇴장 연출 (13 §2)**: 팝 0.15초 → 제자리 0.4초 → 소실점으로 0.8초 동안 축소·페이드. 소실점 쪽 화면 가장자리에 중심 항성 색의 희미한 빛. 런 행성에도 소실점을 광원으로 한 명암.

**수치**: 새 수치는 전부 `GameParams`(Planet departure, Result solar system, Skill tree view 절)에 있다. `planetLifetimeSec`는 퇴장 연출 세 구간으로 대체되어 지웠다.

## 2. 합격 기준 확인

| 기준 | 결과 |
|---|---|
| 12 §9: 1920×1080과 1280×720에서 링 3까지 한 화면 | 1920×1080 확인(링 3 상태에서 0.92배로 링 4까지 보임). 1280×720은 같은 16:9라 캔버스 배율만 바뀌고 배치가 같다(직접 확인은 못 함) |
| 12 §9: 아무것도 안 사면 3초 안에 다음 런 / 13 §9: Space 두 번 | 확인. 결과 → Space → 트리 → Space → 런 |
| 13 §9: 소행성 500개 런에서도 60fps | 티어 1~3 각 500개(소행성대 3개, 스프라이트 934개)에서 에디터 88fps |
| 13 §9: 런 1과 런 10 비교 | 봇 기준 런 1은 궤도 1개에 소행성 14개, 런 10은 궤도 2개에 혜성 14개(수입 14 → 126). 궤도가 느는 것은 보이지만, 봇이 최고 티어만 만들어 행성 수는 같다. 링 3 이후(궤도 3개 이상, 소행성대)부터 차이가 커진다 |
| 12 §9: 처음 보는 사람이 설명 없이 사고 다음 런 / 캡처가 스토어용으로 쓸 만한가 | 사람 확인 필요 |

## 3. 기획 세션이 볼 것

1. **결과 화면이 런 종료 시점의 해금 상태를 보여 준다.** 결과를 본 뒤 트리에서 관문을 사면, 새 궤도는 다음 결과 화면부터 생긴다.
2. **런 10까지 결과 화면의 변화가 작다.** 봇은 최고 해금 티어만 만들기 때문에 낮은 궤도가 비고 행성 수가 비슷하다. 사람이 일부러 낮은 티어로 놓으면 궤도가 채워진다. 초반에 성장을 더 보이게 하려면 이전 런보다 늘어난 부분을 강조하는 연출 같은 방안을 생각할 수 있다.
3. **13 §7 문구("판매")**는 그대로다(로컬라이제이션 때 결정).

## 4. 알려진 문제

- **공용 머티리얼의 텍스처 번짐(해결).** 먼지 메시와 선은 스프라이트 머티리얼을 쓰는데 자체 텍스처가 없어, 앞서 그려진 부드러운 빛 스프라이트의 텍스처(가장자리 투명)가 묻어 먼지가 안 보였다. 흰 텍스처를 명시해 고쳤다. 새 비스프라이트 렌더러를 만들 때는 `UIBuilder.UseWhiteTexture`를 불러야 한다.
- `×N` 라벨은 궤도 오른쪽 아래에 고정이라 공전하는 행성과 겹칠 수 있다.
- 결과 화면은 매번 행성 오브젝트를 새로 만든다(최대 약 900개). 런이 끝날 때 한 번이라 문제는 없어 보이지만 풀링 여지가 있다.
- 트리 화면은 매 프레임 노드 67개의 상태와 라벨 문자열을 다시 계산한다(메뉴 화면이라 두었다).
- 동작 확인 흔적(세이브, 로그)은 persistentDataPath의 `tree_view_tests\`, `solar_tests\`로 옮겼다.
