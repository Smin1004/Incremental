## 2. 스태미나 프리셋 키

**F10.** 느슨함 → 제안 → 빠름 → 느슨함 순으로 돈다. 에셋 값이 곧 "제안"이므로 처음 누르면 빠름이다.

```
스태미나 소모: 제안 (홀드 1.5/초, 대기 0.3/초)
```

- 토스트로 프리셋 이름과 두 수치를 함께 보여 준다(1.5초). 이름은 `UIStrings`의 `stamina.preset.<id>`다.
- **런 도중에 눌러도 즉시 반영된다.** `TickRun`이 매 틱 유효 스탯을 다시 계산하므로, 누른 다음 틱부터 새 소모율로 줄어든다. 확인: 제안(1.5/0.3) 상태에서 F10 → 유효 홀드 소모 2.0/0.4로 바뀌는 것을 런 중에 확인했다.
- **저장하지 않는다.** 에셋도, `save.json`도, `settings.json`도 건드리지 않는다. 게임을 다시 켜면 에셋 값(제안)이다.
- 스킬트리의 "스태미나 소모 감소" 노드는 그대로 곱해진다. 프리셋은 감소율이 아니라 기준값을 바꾼다(−50% 노드 + 빠름 프리셋 = 1.0/0.2).
- 런이 끝나면 `run_log.csv`의 `stamina_hold_drain`·`stamina_idle_drain` 칸에 그 런에 쓰인 값이 남는다. 2차 점검에서 어느 프리셋으로 돌린 런인지 로그로 구분된다.

## 4. 스스로 정한 것

1. **키는 F10.** F9는 Shift+F9(세이브 삭제)와 겹치고, F10은 비어 있으면서 F11(연출 강도 순환) 옆이라 "순환" 키끼리 붙는다. 17 §1의 키 표에 F10 줄이 필요하다(기획 문서라 건드리지 않았다).
2. **프리셋을 `GameParams`에 뒀다.** F11의 `effectSteps`처럼 `DebugTools` 필드로 둘 수도 있었지만, 프롬프트가 "새 수치도 GameParams나 CelestialTable에" 이므로 데이터 에셋에 두고 Validate Data 검사도 붙였다. 프리셋 id마다 `UIStrings` 문자열이 있어야 오류가 난다.
3. **프리셋은 기준값을 바꾸고 노드 감소는 유지한다.** `Stats.Compute`에 기준 소모율 2개를 받는 오버로드를 더했다. 결과값을 덮어쓰면 트리 노드 효과가 사라져서 "스태미나 소모 감소"를 산 런에서 프리셋 비교가 무의미해진다.
4. **A3 꼬리 수치는 캡처를 보고 골랐다.** 처음에 폭 0.32·벌어짐 0.14·페이드 2.6까지 좁혔더니 꼬리가 코마에 묻혀 혹처럼 보였다. 0.4 / 0.2 / 1.8이 "짧고 퍼지는 꼬리"에 가장 가까웠다(후보 여섯 가지를 같은 화면에서 비교). 길이 3.5는 지시대로 두었다.
5. **"코마 글로우 0.9 → 1.1"은 `glowSize`로 읽었다.** 혜성의 `glowStrength`는 0.75여서 0.9와 맞는 값은 `glowSize`뿐이다. 세기를 뜻한 것이었다면 `glowStrength`를 1.1로 바꾸면 된다.
6. **새 꼬리 필드의 기본값은 예전 셰이더 상수와 같게 두었다.** 0.5 / 0.3 / 1.3. 꼬리가 없는 티어 10개의 에셋 값이 이 기본값으로 채워졌을 뿐 외형은 그대로다.

## 5. 알려진 문제와 확인 필요

1. **"×N" 라벨이 짧아졌다.** 한 번에 여러 개를 만들 때 천체 위에 뜨는 `×3` 라벨의 수명이 팝+정지+이동/2로 계산되어 0.95초 → **0.525초**가 됐다(`GameRoot.SetCountLifetime`). A2에서 파생된 값이라 그대로 뒀다. 2차 점검에서 읽기 어려우면 이 식만 분리하면 된다.
2. **혜성 꼬리가 짧다고 느낄 수 있다.** 표시 크기가 26px이라 3.5 반지름은 약 45px이고, 코마가 27px까지 차지해서 꼬리가 코마 밖으로 18px쯤만 나온다. `comet_tail_compare.png`를 보고 더 길게 원하시면 `tailLength`만 올리면 된다(4.2까지 비교해 봤고 그쪽도 자연스러웠다). 티어 2의 `sizePx`를 올리는 쪽도 있다.
3. **스태미나 최종값은 2차 점검에서 고르는 것이다.** 지금 기본은 "제안"(1.5/0.3)이고 기본 런 40초 예상이다. 고르신 프리셋을 `staminaHoldDrain`·`staminaIdleDrain`에 박으면 되고, 그때 프리셋 배열은 남겨 두어도 Validate Data는 통과한다(에셋 값이 프리셋 중 하나가 아니면 경고만 난다).
4. **A2·A3의 해석**은 18 §F의 확인 1·2를 그대로 따랐다(생성된 천체의 잔류, 혜성 꼬리). 다른 것을 뜻했다면 값 되돌리기는 1분이다.
5. **토스트 캡처는 화면에 붙여 두고 찍었다.** 에디터 창이 포커스를 잃으면 프레임이 1초 이상으로 늘어져 토스트 수명 1.5초가 한 프레임에 지나가 버린다. 같은 토스트 요소에 실제 코드 경로(`CycleStaminaPreset`)가 넣은 문구를 그대로 띄워 두고 찍었다. 실제 플레이(60fps)에서는 1.5초 동안 보인다.
6. **에디터에서만 확인했다.** 개발 빌드는 만들지 않았다. 디버그 키는 `UNITY_EDITOR || DEVELOPMENT_BUILD`에서만 동작하는 기존 조건 그대로다.
