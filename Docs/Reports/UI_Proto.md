3. **Pretendard를 계속 쓸지.** 임시로 넣어 둔 상태다. 바꾸려면 `UITheme`의 `fontRegular` / `fontBold`에 다른 폰트 파일을 넣으면 된다(§3).

## 1. 만든 것

- **Pretendard** Regular, SemiBold (`Assets/Game/UI/Fonts/`, SIL OFL 1.1, 라이선스 파일 `Pretendard-LICENSE.txt` 동봉). 공식 저장소 `orioncactus/pretendard`의 정적 OTF다. OFL은 게임에 넣어 배포하는 데 제한이 없다(폰트만 따로 파는 것만 금지).
- **TextMeshPro 전환.** `UIBuilder.CreateText`가 TMP 글자를 만든다. HUD, 결과, 트리, 엔딩 크레딧, 갤러리의 글자가 전부 Pretendard로 나온다. OS 폰트(맑은 고딕) 로드는 지웠다.
- **고정폭 숫자.** 숫자 10개가 가장 넓은 숫자의 폭을 쓴다. 값이 바뀌어도 폭이 흔들리지 않고, 결과 목록의 수가 자리별로 맞는다.
- **`UITheme`** (`Assets/Game/Data/UITheme.asset`). 폰트, 글자 크기 6단계, 방향 A/B/C의 팔레트와 도형, 스태미나 색, 애니메이션 시간. **플레이 중에 인스펙터에서 바꾸면 바로 반영된다**(크기와 배치 값은 다음 플레이부터, §3).
- **UI 셰이더 하나** (`Incremental/UIPanel`). 패널, 버튼, 키 칩, 막대, 배지를 전부 그린다. 텍스처 없음. 매개변수: 채움, 테두리, 모서리 반경, 모서리 브래킷, 눈금, 가장자리 빛, 유리 하이라이트, 바깥 그림자, 막대 칸 나눔.
- **버튼** (`UIButton`). 호버하면 빛나고 글자가 강조색으로, 누르면 0.96배로 줄고, 옆에 키 힌트 칩(`Space`)이 붙는다.
- **결과 화면**: 새 패널과 버튼, 수입이 0.8초 동안 올라가고 끝에서 한 번 튐, 배율은 1 이상이면 강조색·미만이면 흐리게, 최고 기록 갱신 배지(한 번 반짝임), 행성 미니 아이콘(행성 셰이더 그대로), 행이 위에서부터 0.05초 간격으로 등장.
- **스태미나 (a)**: 새 막대. 50%까지 청백, 35%에서 주황, 20%에서 적색. 20% 아래에서 맥동.
- **스태미나 (b)**: 중력 고리가 위에서 시계 방향으로 잔량만큼만 그려진다. 색과 맥동은 (a)와 같다. 뒤에 흐린 전체 고리가 남고, 위쪽 막대는 얇은 띠로 줄어든다.
- **연출 강도(F11)**: UI의 가장자리 빛, 호버 빛, 배지 반짝임, 맥동 깊이, 등장 시간, 누름 축소가 전부 연출 강도를 곱한다. 0이면 결과 화면이 바로 완성 상태로 뜬다(확인함).

## 2. 확인 방법

| 키 | 동작 |
|---|---|
| `U` | UI 방향 A(관측 기기) → B(유리 패널) → C(패널 없음). 어느 화면에서든 바로 바뀐다 |
| `G` | 스태미나 표시 (a) 위쪽 막대 ↔ (b) 중력 고리. 런 중에 바로 바뀐다 |
| `F1` | 오버레이. 맨 아래 줄 끝에 `UI 방향 B [U]   스태미나 b [G]`가 나온다 |
| `F11` | 연출 강도 1 → 0.5 → 0. UI의 빛과 움직임도 따라간다 |
| `Home` | 런을 바로 끝내고 결과 화면을 본다 (기존 키) |

- 두 키 모두 누를 때 화면 아래 토스트와 콘솔 `[UI] direction: B 유리 패널` / `[UI] stamina display: (b) 중력 고리`가 찍힌다. 저장하지 않으므로 다시 켜면 `UITheme.direction` / `staminaMode` 값으로 시작한다.
- **글자 키로 정했다.** F1~F12와 숫자 줄이 다 차 있고, 방향키 묶음(Insert, Home 등)은 지난번에 게임에 닿지 않았다. 키 입력은 에디터에서 입력 시뮬레이션으로 확인했다. 개발자 키보드에서 안 되면 F1을 켜고 눌러 콘솔의 `[Debug] key pressed: …`를 보면 된다.
- **R7 확인**: 결과 화면이 뜨고 0.3초 뒤(등장 중) Space → 바로 트리, 다시 Space → 런 시작. 결과가 뜬 때부터 **0.68초**였다. 전환을 추가하지 않았으므로 Space 사이 대기가 없다.
- 최고 기록 배지는 **이전 풀 런보다 수입이 높을 때**만 붙는다. 지금 세이브에서 한 런을 끝까지 하면 붙는다.

## 6. 알려진 문제

- **빌드에서는 확인하지 않았다.** 폰트 에셋을 실행 중에 만드는 방식이라 빌드에서 한 번 봐야 한다. TMP 셰이더는 `UITheme.textShader`가 참조해서 빌드에 들어가게 해 두었다.
- **트리 화면과 HUD의 재화·수입 글자는 예전 모양 그대로다**(폰트만 Pretendard). "다음 런" 버튼도 기본 파란 버튼이다. 2단계 몫이다. 트리 도움말 겹침도 그대로다.
- 고정폭 때문에 숫자 `1` 양옆이 넓어 보인다. 싫으면 `tabularDigits`를 끈다.
- B는 배경 흐림이 없는 반투명이라 밝은 성운 위에서는 회색에 가깝게 보인다. 진짜 유리 느낌(뒤 흐림)은 셰이더 하나로는 안 된다.
- C는 버튼에 형태가 없어서 누를 곳이 글자뿐이다(클릭 영역은 같다).
- (b) 고리는 중력원이 화면 가장자리에 있으면 일부가 화면 밖으로 나간다.
- 밝은 먼지 위에서 HUD 글자와 (a) 막대 아래 숫자가 잘 안 읽힌다. HUD 전체 스타일(2단계)에서 다뤄야 한다.

## 7. 만든 것

**HUD (A)**
- 위쪽 가장자리에 아래로 옅어지는 어두운 베일을 깔았다(`UIRole.Veil`). 재화·런 번호(왼쪽), 이번 런 수입(오른쪽)이 라벨(흐림) + 값(굵게) 두 줄이고, 수입은 금색이다.
- 수입은 새 값으로 0.35초 동안 굴러 올라가고 바뀔 때 한 번 튄다.
- **능력 충전 호**: 쿨다운이 있는 능력(수축 청백, 유성 주황)마다 중력 고리 바로 바깥에 얇은 호가 차오르고, 발동 순간 전체 고리가 넓어지며 한 번 밝아진다. 위성은 상시라 없다. `AbilitySystem.Get(id)`로 `Charge`·`Level`·`EffectAge`를 **읽기만** 한다.

**트리 (B)**
- `TreeView`의 색·크기·시간 상수가 전부 `UITheme.tree`로 갔다.
- 위·아래 바가 베일 띠다. **도움말이 노드 비용 글자와 겹치던 문제**는 아래 띠가 뒤의 노드를 어둡게 눌러서 해결했다. 헤더는 제목 + "보유 재화" 라벨/값.
- "다음 런" 버튼이 `UIButton`(Space 칩)이고, 툴팁이 패널 셰이더다. uGUI 기본 버튼은 코드에서 지웠다.
- 비용 글자 15 → 18, 대비 상향. 살 수 있는 노드는 0.6Hz로 천천히 맥동한다(빛과 크기).
- **구매 연출**: 노드 점등, 선행 노드에서 연결선을 따라 빛이 흐르고 연결선이 0.6초 밝게 남음, 불꽃 6개, 관문은 그 링 원이 0.8초 밝아짐.
- 해금 노드가 크다: 관문 32, 먼지 종류·능력 26, 스탯 18.

**화면 전환 (C)**: 런 → 결과 → 트리 → 런 사이에 0.3초. 어두운 베일이 들어왔다 나가며 카메라가 4% 줌인하고, 중간에서 화면이 바뀐다. 런이 끝난 직후에는 런 화면이 중간 지점까지 남는다. **R7**: 결과가 뜬 뒤 0.3초에 Space, 0.4초 뒤 다시 Space → **0.86초**에 다음 런이 시작됐다(시안 때 0.68초, 전환 둘이 더해진 값). 전환 중에 Space를 또 누르면 바로 바뀐다.

**결과 화면 보완 (D)**: ▲ 증감과 "새 천체" 색이 `UIDirection.deltaUp` / `newTag`다. A는 청백 ▲, 금색 새 천체. `GameParams.deltaUpColor` / `newTierColor`는 지웠다.

**월드 연출 (E)**
- **과노출 억제** 네 가지, 전부 `GameParams`에 있고 디버그 키 `X`로 한꺼번에 켜고 끈다.
  1. 밀도 감쇠: 화면 먼지가 `dustDensityRef`(1,500)개를 넘으면 모든 먼지와 궤적이 `√(ref/수)`만큼 어두워진다. 바닥 `dustDensityFloor` 0.5. 링 11(약 3,500~6,000개)에서 0.5~0.65.
  2. 중심 감쇠: 형성 중인 천체 반지름 × `dustCenterDimRadii`(2.5) 안의 먼지와 궤적이 중심으로 갈수록 `dustCenterDim`(0.25)까지 어두워진다. 천체 표면이 드러나게 하는 것은 이것이다.
  3. 들뜸 감쇠: 들뜸 밝기를 `1 + (종류 크기 − 1) × exciteSizeFalloff`(1.0)로 나눈다. 대형 먼지가 흰 덩어리가 되던 것.
  4. 밝기 상한: 먼지 하나의 밝기를 `dustBrightCap`(1.5)에서 자른다. 2는 예전 값으로, 채널마다 1에서 잘려 색이 흰색으로 바뀌던 지점이다.
- **관문 확장 고리**: 관문을 사서 월드 배율이 움직이기 시작하면(`GameRoot.WorldExpanding`) 화면 중앙에서 고리 하나가 줌아웃 0.6초에 맞춰 퍼진다(`GateExpandFx`, FxRing 머티리얼). 트리 화면 뒤에서 보인다.
- **초반 먼지**: 링 1·2에서 먼지를 1.6×/1.3× 크게, 1.35×/1.15× 밝게 그린다(`earlyDustSizeMult` / `BrightMult`). 수와 질량은 그대로다.

## 12. 알려진 문제

- **빌드에서는 확인하지 않았다.**
- 밀도 감쇠가 전체 밝기를 낮춘다. 개발자 취향에 따라 `dustDensityRef`를 3,000 정도로 올릴 수 있다.
- 과노출 비교 캡처의 "끔"은 같은 프레임이 아니라 0.8초 뒤다. 수축 비교는 다음 발동이라 장면이 다르다.
- 충전 호는 중력원이 화면 가장자리에 있으면 일부가 잘린다(스태미나 (b)와 같은 문제).
- 능력을 강제로 켜지 않은 보통 플레이에서는 능력 노드를 산 뒤에야 호가 보인다.
- 트리 캡처에서는 포커스 줌이 작아 비용 글자가 작아 보인다(실제 확대 배율에 비례한다).
- 전환의 줌인은 카메라 orthographicSize를 곱하는 방식이라, 결과 화면의 태양계도 같이 살짝 커진다.
- 에디터 Game 뷰가 포커스를 잃으면 키 입력이 들어가지 않는다(Input System 설정). 개발자 플레이에는 영향이 없다.

| 하지 않은 것 | 축마다 색조 달리하기(백로그 후보), 구매 연출의 이동 광점을 곡선으로 |

## 13. 만든 것

- **팔 7개 균등 배치.** 시드의 축 각도(12 §5)를 뷰에서 팔로 묶는다: 관문 90°에서 반시계로 360/7°씩 — 관문, 행성+파편, 스태미나, 능력, 판매, 중력+추종, 먼지+먼지 종류. 같은 팔의 하위 축은 `armSubOffsetDeg`(8°) 단위로 옆에 놓인다(파편 −0.5, 행성 +0.5 / 추종 −0.5, 인력 +0.5, 반경 +1 / 먼지 쌍 −1·−0.5·0, 먼지 종류 +1). 시드 데이터(`NodeDef.angleDeg`)는 그대로고, `UITheme.tree.arms`를 끄면 이전 방사형으로 돌아간다.
- **나선.** 노드 각도 = 팔 각도 + 하위 축 오프셋 + `armTwistDeg` × 링. 모든 팔이 같이 돌아 겹치지 않는다. 링 11에서 12° × 11 = 132°.
- **곡선 연결.** 연결선을 `UICurve`(새 uGUI 폴리라인)로 그리고, 양 끝의 반지름과 각도를 `edgeSegments`(10) 조각으로 고르게 보간한다. 같은 팔을 따라 오르는 연결은 나선을 따라 휘고, 다른 팔로 건너가는 연결(관문 → 먼지 종류·파편·행성 임계값)은 짧은 쪽으로 돈다.
- **T 키**로 비틀기 0 / 8 / 12 / 16° 순환 (토스트 "트리 나선 비틀기: 링당 N°", 콘솔 `[Tree]` 로그). 노드와 연결선이 즉시 다시 놓인다. 저장되지 않으며, 새로 켜면 `UITheme.tree.armTwistDeg`(12)로 시작한다.

## 16. 스펙과 다르게 한 것, 정한 것

1. **팔 순서는 지금 축의 순환 순서**를 지켰다 (관문을 위에 두고 반시계로). 스펙의 나열 순서(관문, 먼지, 행성, …)와는 다르다 — 순서를 바꾸면 익숙한 자리가 흐트러진다.
2. **다른 팔로 건너가는 연결은 그대로 둔다.** 시드가 `gate_t3 → dust_medium`, `gate_t2 → r2_threshold`, `gate_t3 → frag_unlock`처럼 관문을 선행 조건으로 적은 곳이다. 곡선이 팔 사이를 가로지른다. 시드를 고치는 일은 기획 몫이라 두었다.
3. **구매 연출의 이동 광점**(26 §5.3)은 아직 직선으로 달린다. 곡선 연결 위를 달리게 하지 않았다.
4. **축 색조**는 하지 않았다.

## 17. 알려진 문제

- 비틀기를 키로 바꾸면 **뷰의 초점은 그대로**라 바깥 링이 화면 밖으로 나갈 수 있다. 드래그로 옮기면 된다.
- 하위 축 오프셋이 비틀기와 합쳐져 바깥 링에서는 같은 팔의 두 노드가 각도로는 가깝고 반지름으로만 떨어진다. 12°에서 겹침은 없었다(캡처).
