# 특수 능력 3차 작업 프롬프트 (구현 세션용)

2026-10-01. 수축 범위를 화면 기준으로 바꾸고, 화면 확인이 필요 없는 작은 것 둘을 같이 한다.

```text
특수 능력 3차: 수축 범위를 화면 기준으로, MaxReduction 데이터화, 불필요 패키지 정리. abilities 브랜치에서 이어서 한다.

스펙은 Docs/24_Ability_Spec.md §17이다.

[이번 작업의 성격]
1·2차와 같다. 봇 완주 런, 밸런스 조정, 빌드 성능 측정, 새 EditMode 테스트는 하지 않는다.
기존 EditMode 테스트는 마지막에 한 번만 돌린다. Validate Data는 체크포인트마다 돌린다.

[작업 순서]
A. 수축 범위를 화면 기준으로 (24 §17.1)
   - 범위 = 화면 반대각선 × 비율. 해금 rangeScreenStart(0.4)에서 최종 레벨 전역까지 레벨마다 같은 간격.
   - 최소 범위 = 중력 반경 × rangeMinRadii(1.5).
   - rangeRadiiBase와 rangeRadiiPerLevel은 없앤다. 전역의 정의, 고리 표시, ringSec, 힘은 그대로.
   - 레벨 수가 늘어도(노드 maxLevel을 5로 바꿔도) 코드 수정 없이 간격이 다시 나뉘어야 한다. 시드에서 maxLevel만 바꿔 한 번 확인하고 3으로 되돌려라.
B. Stats.MaxReduction을 GameParams로 (값 0.9 그대로, Validate Data에 추가) (24 §17.2)
C. 불필요 패키지 정리 (24 §17.2)
   - com.unity.ai.inference, com.unity.multiplayer.center, com.unity.visualscripting, com.unity.timeline, com.unity.collab-proxy.
   - 지우기 전에 코드와 에셋이 참조하는지 확인하고, 참조하는 것은 남기고 보고서에 적는다.
   - 목록에 없는 패키지는 건드리지 마라. 특히 Unity MCP 패키지. com.unity.ai.assistant는 다시 넣지 않는다.
D. 캡처(링 5와 링 11에서 각각 수축 해금과 Lv2, 4장), 기존 테스트 한 번, 보고서
체크포인트마다 커밋한다.

[지킬 것]
- 위성은 건드리지 마라. 여러 기가 같은 순간에 근점을 지나는 것은 의도다(24 §17). 엇갈리게 고치지 마라.
- exciteDriftRelaxMult는 0.3 그대로 둔다. 개발자 확인 전이다.
- 새 수치는 전부 데이터 에셋에. 코드 상수 금지.
- 스펙이 모호하면 간단한 쪽으로 정하고 보고서에 적는다. 멈추지 마라.
- 커밋 메시지는 한국어로 쓴다 (CLAUDE.md).

[끝나면]
Docs/Reports/Abilities_Proto.md 끝에 "3차" 절을 붙인다. 바꾼 값과 새 값 표, 지운 패키지와 남긴 패키지(이유), 캡처 목록, 알려진 문제를 짧게 적어라. main 병합은 하지 않는다.
```

## 판단

- **수축만 바꿨다.** 위성 원점과 표류 감속 약화는 개발자가 더 지켜보거나 아직 확인하지 못했다. 바꾸면 확인할 것이 쌓인다.
- **화면 확인이 필요 없는 둘을 끼웠다.** `MaxReduction` 데이터화와 패키지 정리는 동작이 바뀌지 않아 개발자가 볼 것이 늘지 않는다. 다듬기 단계로 미뤄 둔 다섯 중 시각 작업 셋(관문 확장 연출, 중심부 포화 억제, 초반 먼지)은 능력 확인이 끝난 뒤에 한다.
- **레벨 확장을 미리 시험하게 했다.** 개발자가 강화 레벨을 늘릴 예정이다. 시드에서 `maxLevel`만 바꿔 간격이 다시 나뉘는지 한 번 보는 것으로 충분하다.
