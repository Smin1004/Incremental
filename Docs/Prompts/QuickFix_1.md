# 즉시 수정 1차 프롬프트 (구현 세션용)

1차 점검에서 나온 불편 3건만 고친다. 반나절 안에 끝나고, 끝나면 개발자가 2차 점검을 한다.

```text
점검 1차 불편 사항 즉시 수정.

지시는 Docs/18_Feedback_Round1.md §A다. 그 절만 읽으면 된다. 배경이 필요하면 Docs/17_Playtest_Guide.md(디버그 키)와 Docs/14_Planet_Visual_Spec.md(비주얼 수치)를 본다.

[시작 전에]
1. ending 브랜치를 main에 병합해라. 5주차 결과는 개발자가 확인했다.
2. persistentDataPath에 개발자가 플레이한 run_log.csv나 save.json이 있으면 지우지 말고 human_playtest_<시각>\ 폴더로 옮겨 보존해라.
3. 커밋되지 않은 Docs/ 기획 문서(16, 17, 18, Prompts)를 내용은 건드리지 말고 "기획 문서 갱신"으로 커밋해라.
4. main에서 브랜치 quickfix1을 만들어 작업해라.

[할 일]
A1. 스태미나: 홀드 소모 1.0 → 1.5, 대기 소모 0.2 → 0.3. 그리고 디버그 키 하나에 프리셋 순환을 붙여라. 느슨함(1.0/0.2) → 제안(1.5/0.3) → 빠름(2.0/0.4). 현재 프리셋 이름을 토스트로 보여 주고, 런 도중에 바꿔도 즉시 반영되게 한다. 저장하지 않는 런타임 값이다.
A2. 생성된 천체의 잔류: 제자리 정지 0.4 → 0.15초, 소실점 이동 0.8 → 0.45초.
A3. 혜성(티어 2) 꼬리: 길이 6 → 3.5, 폭을 좁히고 끝 페이드를 강하게, 코마 글로우 0.9 → 1.1. 갤러리(F8)에서 수정 전후를 비교해 캡처를 남겨라.

[지킬 것]
- 전부 데이터 값이다. 새 수치도 GameParams나 CelestialTable에 두고 시드 코드와 Validate Data를 맞춘다. 코드 상수 금지.
- 게임 규칙은 바꾸지 않는다. 흡인 보정, 먼지 종류, 특수 능력은 다음 작업이다.
- 커밋 메시지는 한국어로 쓴다 (CLAUDE.md).

[완료 조건]
EditMode 테스트 통과, Validate Data 오류 0. F8 갤러리에서 혜성 수정 전후 캡처, 런 화면에서 천체 생성과 퇴장 캡처를 Docs/Reports/QuickFix1_Screens/에 남긴다.

[끝나면]
Docs/Reports/QuickFix1.md에 짧게 쓴다. 바꾼 값 표, 스태미나 프리셋 키, 캡처 경로, 스스로 정한 것, 알려진 문제. main 병합은 하지 말고 브랜치 상태로 보고해라.
```

## 이 프롬프트의 판단

- 3건만 넣었다. 개발자가 불편한 상태로 다음 점검을 하지 않게 하는 것이 목적이고, 큰 작업과 섞으면 반나절이 며칠이 된다.
- 스태미나는 값 하나로 못 박지 않고 프리셋 키로 만들었다. 감각 문제라 직접 비교해서 고르는 편이 빠르다.
- A2와 A3는 해석이 틀렸을 수 있다. 값 되돌리기가 1분이라 먼저 진행한다.
