2026-10-06. 시안에서 개발자가 방향 A, 스태미나 (a), Pretendard를 골랐다. 남은 UI 전개와 월드 연출을 한 번에 한다.

[이번 작업의 성격]
프로토타입 방식 그대로다. 봇 완주 런, 밸런스 조정, 빌드 성능 측정, 새 EditMode 테스트는 하지 않는다.

   - 수입이 오를 때 굴러 올라가고 바뀔 때 살짝 튄다.
   - 능력 충전 호: 쿨다운이 있는 능력마다 중력 고리 바로 바깥에 얇은 호. 능력 코드는 읽기만 한다.

   - 관문 확장 연출(고리 한 번 퍼짐), 초반 먼지 크기·밝기(수와 질량은 그대로).
F. 캡처(26 §9.4), 기존 테스트 한 번, 보고서.

## 판단

- **2단계와 3단계를 합쳤다.** 개발자가 확인을 미루는 편이라 확인 횟수를 줄이는 쪽이 일정에 낫다. 과노출은 HUD 글자가 안 읽히는 원인이기도 해서 따로 떼면 HUD 확인이 반쪽이 된다.
- **과노출은 목표만 주고 수단은 워커에게 맡겼다.** 원인이 들뜸, 궤적 누적, 먼지 밀도 중 어디에 얼마나 있는지는 직접 재 봐야 안다. 대신 키 하나로 전후를 비교하게 했다.
- **능력 충전 호를 넣었다.** 스태미나가 (a)로 정해져 중력 고리 둘레가 비었다. 능력이 언제 터지는지 보여 주면 "능력이 뭘 하는지 모르겠다"는 문제를 미리 막는다. 능력 코드는 읽기만 하므로 개발자 확인 전이어도 안전하다.
