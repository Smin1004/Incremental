# 위성 견인 + 빌드 확인 작업 프롬프트 (구현 세션용)

> **아직 보내지 않았다면 보내지 않는다.** 같은 내용이 [Proto5_Build.md](Proto5_Build.md)의 A와 F에 들어 있다.

2026-10-07. 개발자 확인 뒤 남은 위성 보강 하나와, 미뤄 온 빌드 확인을 한 번에 보낸다. 위성을 먼저 고쳐야 빌드 성능 표에 최종 위성이 들어간다.

```text
위성 견인과 빌드 확인. abilities 브랜치에서 이어서 한다.

개발자가 능력 2·3차와 UI 2·3단계를 확인했다. 결과는 Docs/24_Ability_Spec.md §18, Docs/26_UI_Pass_Spec.md §10에 있다.
수축과 유성은 확정이다. 위성만 "끌고 오는 힘이 아쉽다"는 회신이 있었다.

[이번 작업의 성격]
A는 프로토타입 방식(봇 완주 런, 밸런스, 새 테스트 없음)이다. B~D는 빌드 확인이다.
기존 EditMode 테스트는 마지막에 한 번만 돌린다. Validate Data는 체크포인트마다 돌린다.

[작업 순서]
A. 위성 견인 (24 §18.1)
   - 위성 핵 반경(중력 반경 × towRadiusShare 0.15) 안의 먼지는 속도가 위성 속도 쪽으로 끌려간다(towRate 6/초, 0이면 끔).
   - 들뜬 동안 먼지 최고 속도에 exciteSpeedCapMult(1.8)를 곱한다.
   - pullShare 1.0 → 1.4. 궤도 값은 그대로.
   - 2차와 같은 장면에서 10초 홀드 포획 수를 다시 잰다(2차: 위성 없음 717, 1기 871, 4기 1,116). towRate 0과 6을 같이. 원점에서 근점으로 오는 0.5초를 캡처 3장으로.
B. 윈도우 빌드를 만든다. 7주차의 -perfbench 하네스가 들어가는 같은 구성으로.
   빌드에서만 깨질 수 있는 변경이 셋 쌓였다: 패키지 5개 제거, TextMeshPro와 실행 중 Pretendard 동적 SDF 폰트 생성, 능력·화면 밖 먼지·과노출 억제의 비용.
C. 빌드를 실행해 확인한다. 한글이 Pretendard로 나오는지, HUD·결과·트리가 에디터와 같은지, 전환과 능력이 동작하는지. 화면마다 캡처 1장.
D. -perfbench를 돌린다. 7주차 perf_final과 같은 장면에 더해 "런, 먼지 8,000 + 궤적 300 + 능력 전부(최대 레벨) + 화면 밖 먼지" 장면을 추가한다. 7주차 값과 나란히 표로.
   리눅스 빌드 지원 모듈이 설치돼 있으면 리눅스 빌드도 만들어 실행 파일이 생기는지만 확인한다. 없으면 없다고 적는다.
체크포인트마다 커밋한다.

[지킬 것]
- B~D는 고치는 작업이 아니다. 빌드가 깨지거나 화면이 다르면 최소한으로 고쳐 빌드가 되게만 하고, 무엇을 왜 고쳤는지 적는다.
- 성능이 7주차 목표(먼지 8,000 + 궤적 300에서 평균 60 / 99퍼센타일 50) 아래면 최적화하지 말고 어느 비용이 늘었는지만 적는다.
- 위성 외의 능력, UI, 트리 배치는 건드리지 않는다. 트리 배치는 개발자 의도 확인 뒤 따로 한다.
- 새 수치는 전부 데이터 에셋에. 코드 상수 금지.
- CLAUDE.md의 빌드와 성능 규칙을 따른다. com.unity.ai.assistant는 없어야 한다.
- 개발자 세이브는 작업 전에 복사해 두고 끝나면 제자리에 되돌린다. 빌드 실행도 같은 세이브 경로를 쓴다.
- 커밋 메시지는 한국어로 쓴다 (CLAUDE.md).

[끝나면]
위성 결과는 Docs/Reports/Abilities_Proto.md 끝에 "4차" 절로(포획 수 표, 캡처, 바꾼 값).
빌드 결과는 Docs/Reports/Build_Check1.md에(빌드 결과, 화면 확인 캡처, 성능 비교 표, 고친 것, 알려진 문제). main 병합은 하지 않는다.
```

## 판단

- **위성 원인은 속도 상한이다.** 수치를 키우는 것보다 "핵에 걸린 먼지가 위성과 함께 움직이는" 견인이 원하는 그림(덩어리를 끌고 들어옴)에 바로 닿는다. 속도 상한을 같이 풀지 않으면 견인이 걸려도 먼지가 따라가지 못한다.
- **위성을 먼저, 빌드를 나중에** 둔 것은 성능 표에 최종 위성 비용이 들어가게 하려는 것이다.
- **main 병합은 다음 작업 첫 단계로 미뤘다.** 빌드가 통과한 것을 보고 병합하는 편이 안전하다.
