# 13차: 스킬트리 v2 (구현 세션용)

2026-10-15. 스킬트리를 카테고리 5개와 곁가지 구조로 다시 만든다. **두 단계다.** 1단계는 배치·아이콘 시안을 만들고 **멈춰서 개발자 회신을 기다린다.** 2단계는 회신을 받은 뒤 나머지를 한다.

```text
13차: 스킬트리 v2. main 브랜치에서 한다.

스펙: Docs/29_SkillTree_v2.md (전부). 관련: 28 §2.2(끝없는 판 시간 노드 제거), 26 §12(트리 화면 스타일). Docs/에 커밋 안 된 기획 변경이 있으면 먼저 "기획 문서 갱신"으로 커밋해라.

[두 단계]
1단계(시안)를 끝내면 보고하고 멈춰라. 개발자 회신을 받은 뒤 2단계를 한다.
회신에 규칙 노드 선택이 없으면 29 §5의 ★ 16개(T1 T2 T3 T5 / D1 D3 D4 / G1 G2 G3 / C1 C2 C3 C4 / A1 A2)로 한다.

==== 1단계: 배치와 아이콘 시안 (약 0.5일) ====
A1. 시드 뼈대: 29 §3의 수치 줄과 관문·능력 해금으로 노드를 만든다. 규칙 노드 ★16개는 효과 없는 빈 노드로 권장 링에 둔다. 비용과 효과 값은 아직 대충이어도 된다. 기존 NodeTable은 백업 파일로 남겨 두고 새 시드로 다시 만든다.
A2. 배치(29 §2, §3.5): 카테고리 5개가 72°씩(천체 90°, 먼지 18°, 중력 306°, 능력 234°, 시간 162°). 줄기는 가운데를 지나 바깥으로, 곁가지는 줄기에서 ±30° 안. 링이 멀어질수록 바깥. 능력은 해금 노드가 줄기에 있고, 능력마다 갈래가 왼쪽·오른쪽 번갈아 갈라져 노드 3~4개, 링 2개 안에서 끝난다. 카테고리 구역끼리 겹치지 않게.
A3. 화면(29 §6): 카테고리 색, 노드 = 색 원 + 셰이더로 그린 기호 + "Lv x/y". 기호는 스탯 종류별 12개 안팎(텍스처 없이). 규칙 노드는 이중 테두리. 열린 링의 바로 다음 링만 회색으로 보이고 그 뒤 링은 숨긴다.
A4. 캡처: 트리 전체를 링 3 / 링 7 / 링 11 상태로, 나선 비틀기 0°와 16° 각각(6장). 기호 전부를 한 장에 모은 기호표 1장. 한 카테고리를 확대한 장면 1장(능력 갈래). 회색 미리보기가 보이는 장면 1장.
A5. 보고서 Docs/Reports/TreeV2.md에 "1단계" 절: 캡처, 노드 수(카테고리별·링별), 개발자가 고를 것(비틀기 0°/16°, 기호 세트 손볼 곳, 규칙 노드). 커밋하고 멈춰라.

==== 2단계: 나머지 (회신 뒤, 약 2~2.5일) ====
B1. 시드 확정 (29 §3, §4):
   - 수치 줄마다 효과 총합을 지금 트리(v1)의 같은 스탯 총합과 같게. 예외: 판 시간은 링마다 +9초(링 10까지 +90초), 끝없는 판 시간 노드는 없앤다. 반경은 v1 값 × 0.7을 노드에 직접 넣고 GameParams.gravityGrowthScale은 1로.
   - 수치 노드 대부분 ×5, 비용은 링 공식 그대로, 레벨마다 ×1.35. 규칙 노드 비용은 임시로 그 링 공식 × 1.5.
   - 새 스탯 줄: 먼지 질량(dust_mass, 링 5·7·9·11, ×3), 먼지 최고 속도(링 3·6·9, ×3), 능력 쿨다운 감소(ability_cooldown). 효과 코드가 없는 스탯이면 붙인다.
   - 이름: 먼지 종류 "결정 먼지" → "광석 먼지", 판매 배율 "판매 비용" → "판매 가격" (29 §8, id는 그대로).
B2. 세이브: 버전 5. 트리를 초기화하고 그동안 쓴 재화를 전부 돌려준다(관문 포함, v1 비용표로 계산). 해금 티어는 관문 레벨에서 다시 계산되므로 링도 처음부터다. 개발자 세이브는 복사본으로 먼저 확인하고, 돌려받은 재화와 다시 산 결과를 보고서에 적어라.
B3. 규칙 노드 효과 (29 §5, 고른 것만). 전부 데이터 값(GameParams 또는 노드 효과값)과 콘솔 [Rule] 로그. 처리량을 바꾸는 노드라 밸런스 패스가 값을 정한다. 지금은 스펙의 임시 값으로.
B4. 봇: 규칙 노드도 지금 구매 정책대로 사게 둔다.
B5. Validate Data: 노드 수(140~160), 모든 노드가 가운데에서 이어지는지, 줄별 총합 표(v1 대비)를 Validate 출력이나 보고서에 남긴다.
B6. 테스트: 트리 모양 테스트들을 v2에 맞게 고친다. 규칙 노드는 핵심 셋(T1 유예, C2 n번째 묶음, G2 잔류 중력)에만 짧은 테스트를 더한다. 기존 테스트는 마지막에 한 번.
B7. 빌드 확인: 개발 빌드를 만들고 -perfbench를 돌린다(어댑터 꽂고, 같은 날 대조군 Builds/Win64_proto5). 12차 시각 보강(렌즈 4칸, 성운, 먼 천체)이 처음 빌드에서 재는 것이다. 합성 최악 장면 99퍼센타일이 50 아래면 무엇이 늘었는지만 적어라.
B8. 캡처: 확정 트리 전체(링 3/7/11), 규칙 노드 툴팁 몇 개, 규칙 노드가 작동하는 순간 몇 장(T1 유예 동안 시간 막대, C1 연쇄 숫자, G2 잔류 중력 등).
체크포인트(A, B1+B2, B3, B4~B6, B7, B8)마다 커밋한다.
```

## 판단

- **1단계에서 멈춘다.** 트리 모양과 아이콘은 취향 문제다(27 §4.2). 모양을 먼저 고르면 2단계에서 버리는 작업이 없다. 규칙 노드 선택도 이 회신에 같이 받는다.
- **규칙 노드 기본값은 ★16개다.** 개발자가 "예시가 마음에 든다"고 했고, 회신이 없어도 2단계가 막히지 않게 한다.
- **줄별 총합을 v1과 같게 둔다.** 노드를 쪼개기만 하면 밸런스가 거의 그대로라, 밸런스 패스가 0이 아니라 지금 상태에서 출발한다. 판 시간과 반경만 이미 정한 값을 쓴다.
- **세이브는 초기화하고 재화를 돌려준다** (Q9). 개발자 세이브가 링 11이라, 돌려받은 재화로 v2 트리를 다시 사 보는 것 자체가 새 트리 확인이 된다.
- **빌드 측정을 여기서 한다.** 12차 시각 보강을 빌드에서 잰 적이 없고, 트리 화면 노드 수도 늘어난다(트리 화면 fps).
- **R29를 [지킬 것]에 넣었다.**
