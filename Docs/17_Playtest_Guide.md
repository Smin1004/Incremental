# 17. 점검 안내 (개발자용)

| 항목 | 값 |
|---|---|
| 상태 | 안내 |
| 최종 수정 | 2026-10-12 |
| 대상 | 개발자. 에디터 플레이 또는 개발 빌드 기준 |
| 전제 | `proto6` 브랜치 기준 (10/8 7차 회신 반영까지). 디버그 키는 에디터와 개발 빌드에서만 동작한다 |

## 1. 디버그 키

| 키 | 하는 일 | 점검에서 쓰는 곳 |
|---|---|---|
| **F1** | 오버레이 (FPS, 먼지 수, 틱 ms, 능력 상태). 켜 두면 게임이 받은 키가 콘솔에 찍힌다 | 프레임이 떨어지는 구간 확인. 키가 안 먹는 것 같을 때 |
| **F2** | 성능 모드. 먼지 상한 3,700, 생성 100/초로 런타임 오버라이드. 에셋은 그대로 | 후반 먼지 밀도가 어떻게 보이는지 미리 확인 |
| **F3** | 재화 = max(현재 × 10, 1,000) | 트리를 빨리 열어 보고 싶을 때 |
| **F4** | 오토플레이 봇 켜기와 끄기 | 손 안 쓰고 진행 상황 보기 |
| **F5** | 즉시 저장 | 확인하고 싶은 상태를 남길 때 |
| **F6** | 다음 티어 무료 해금 | 상위 천체를 바로 보고 싶을 때 |
| **F7** | 숫자 표기 전환 (문자 ↔ 과학). `settings.json`에 저장된다 | 표기 취향 확인 |
| **F8** | 천체 갤러리. 티어 1~11을 한 줄로. 마우스 방향이 광원, 휠로 크기 | 행성 외형을 한 화면에서 비교 |
| **Shift+F9** | 세이브 삭제 후 런 1부터 | 깨끗한 새 게임 시작 |
| **F10** | 스태미나 프리셋 순환 | 런 길이 체감 비교 |
| **F11** | 연출 강도 1 → 0.5 → 0 순환 | 섬광이 과한지 판단. 0에서도 진행에 지장 없는지 |
| **F12** | 스크린샷을 세이브 폴더에 저장 | 불편한 장면을 그대로 넘길 때 |
| **End** | 엔딩 시퀀스 재생. 런 사이에만. 저장을 바꾸지 않는다 | 엔딩을 반복해서 보기. 크레딧 확인 (D11) |
| **Home** | 스태미나 즉시 소진 | 런을 바로 끝내고 결과 화면 보기 |
| **Insert** | 중력원 추종 속도 순환: 꺼짐 / 현재값 / ×1.5 / ×2 | 추종 속도 체감 비교 |

### 능력 확인 키 (24 §7)

숫자는 키보드 위쪽 숫자 줄이다(숫자 패드 아님). 트리 상태와 무관하게 켜고, 저장을 바꾸지 않는다. 켜는 즉시 충전되므로 홀드하면 바로 나온다.

| 키 | 하는 일 |
|---|---|
| **1** / **2** / **3** / **4** / **5** | 증폭 결정만 / 수축만 / 위성만 / 유성만 / 블랙홀만 (6차부터 이 순서) |
| **6** | 전부 |
| **0** | 끈다 (트리대로) |
| **=** / **-** | 강화 레벨 올림 / 내림 (0~3). 증폭 결정과 유성은 Lv3 다음이 **Lv4 "진화"**(공명, 유성우) |
| **PageUp** / **PageDown** | 위와 같은 것을 순환으로 |

- 화면 왼쪽 아래에 `능력(강제): 수축 Lv2 9.3초`처럼 나온다. 초는 다음 발동까지 남은 **홀드** 시간이다.
- 발동할 때마다 콘솔에 `[Ability]` 로그가 남는다.
- 능력 수치는 `Assets/Game/Data/AbilityTable.asset`을 인스펙터에서 바꾸면 **플레이 중에 바로** 반영된다. 필드 설명은 [Reports/Abilities_Proto.md](Reports/Abilities_Proto.md) §3.
- 확인하기 좋은 링은 8 이상이다. 지금 세이브가 링 11 상태다.
- **능력을 볼 때 `F11`을 누르지 않는다.** 연출 강도가 0이면 수축 고리, 위성 빛, 먼지 들뜸이 그려지지 않아 능력이 안 되는 것처럼 보인다. 강도가 1 미만이면 능력 줄에 `※ 연출 강도 …`가 붙는다. 보이면 `F11`로 1.0까지 돌린다.

### UI·연출 확인 키 (26)

| 키 | 하는 일 |
|---|---|

- UI 값은 `Assets/Game/Data/UITheme.asset`, 과노출 값은 `GameParams.asset`에 있다. 필드 설명은 [Reports/UI_Proto.md](Reports/UI_Proto.md) §3, §9.

## 2. 두 가지 플레이를 구분한다

| | 1차: 자유 점검 | 2차: 측정 플레이 |
|---|---|---|
| 목적 | 불편한 곳 찾기 | 밸런스 기준이 될 사람 데이터 |
| 디버그 키 | 마음껏 쓴다 | **쓰지 않는다** |
| 시작 | 아무 상태에서나 | Shift+F9로 새 게임 |
| 분량 | 20~30분 | 30분 |
| 로그 | 버린다 | `run_log.csv`를 기획 세션이 분석한다 |

**순서는 1차 → 수정 → 2차다.** 불편한 상태로 30분을 버틸 이유가 없고, 고친 뒤에 잰 데이터가 실제 출시 버전에 가깝다.

F3(재화)과 F6(무료 해금)을 쓰면 그 세이브의 런 기록은 밸런스 자료로 쓸 수 없다. 1차에서 마음껏 쓰고, 2차 전에 새 게임으로 시작하면 된다.

## 3. 1차 점검에서 볼 것

순서대로 하면 20분 정도다.

1. **새 게임 10분.** 디버그 키 없이. 첫 1분에 무엇을 해야 하는지 알겠는지, 런 길이가 지루한지, 트리에서 다음 런까지 가는 길이 번거로운지.
2. **스냅샷으로 링 5, 링 9를 불러와** 각각 한두 런. 후반의 먼지 밀도, 행성 하나 만드는 데 걸리는 시간, 화면이 너무 밝은지.
3. **F8 갤러리.** 천체 11개를 나란히. 마음에 안 드는 외형을 적는다.
4. **End로 엔딩 재생.** 37초가 긴지, 건너뛰기가 자연스러운지.
5. **F11로 연출 강도 0.5와 0.** 어느 쪽이 기본값이어야 하는지.

## 4. 불편한 점을 넘기는 형식

항목마다 네 줄이면 충분하다. 길게 쓸 필요 없다.

```
화면: 런 / 결과 / 트리 / 엔딩 / 갤러리
무엇: 지금 어떻게 되어 있는지
원하는 것: 어떻게 되면 좋겠는지
정도: 거슬림 / 고쳐야 함 / 이대로는 못 하겠음
```

스크린샷이 있으면 F12로 찍어 파일 이름만 알려 주면 된다. 기획 세션이 각 항목을 아래 세 가지로 분류해서 넘긴다.

| 분류 | 처리 | 걸리는 시간 |
|---|---|---|
| 수치 조정 | 데이터 에셋 값만 바꾼다 | 항목당 분 단위 |
| 규칙 변경 | 스펙을 고치고 구현한다 | 항목당 반나절 안팎 |
| 새 기능 | 일정에 넣는다 | 로드맵 조정 |

## 5. 빠르게 고칠 수 있는 것

전부 데이터 값이라 즉시 바꿀 수 있다.

- 먼지: 크기, 색, 밝기, 표류 속도, 반경 밖 어두워지는 정도, 늘어나는 정도.
- 중력: 반경, 가속, 포획 반경.
- 스태미나: 최대치, 홀드 소모, 대기 소모.
- 천체: 티어별 표시 크기, 색, 자전 속도, 고리와 글로우.
- 결과 화면: 궤도 간격, 공전 속도, 등장 시간, 라벨 위치.
- 트리 화면: 링 간격, 노드 크기, 연속 구매 속도.
- 엔딩: 각 단계 길이, 섬광 세기, 크레딧 한 줄 시간.
- 경제: 노드 비용과 효과, 링별 비용 배율, 관문 비용.

반대로 시간이 걸리는 것은 새 화면, 조작 방식 변경, 규칙 변경, 사운드다. 이런 항목이 나오면 로드맵 일정에 영향을 주므로 따로 표시해서 알려 준다.

## 6. 점검 중 알아 둘 것

- 에디터에서 게임 창이 포커스를 잃으면 런이 멈춘다. 의도된 동작이다.
- 런 도중에 플레이를 멈추면 그 런은 중간 종료로 기록된다. 수입은 들어간다.
- 지금 크레딧에는 자리표시 문구가 그대로 나온다. 이름과 제작자명을 정하면 바뀐다.
- 소리는 아직 없다. 7주차 작업이다.
- Esc 메뉴가 없어서 에디터에서는 플레이 정지로, 빌드에서는 창을 닫아 끝낸다.
