# 11. 1주차 프로토타입 스펙 (구현 인계)

| 항목 | 값 |
|---|---|
| 상태 | 확정 |
| 최종 수정 | 2026-09-17 |
| 대상 | 구현 세션. 이 문서만 읽고 시작할 수 있다. 배경이 필요하면 [10_Core_Loop.md](10_Core_Loop.md) |
| 기간 | 5일 |

## 1. 목표

두 가지를 검증한다. 예쁘게 만들지 않는다.

1. 홀드로 먼지를 모아 행성을 만드는 손맛.
2. 스태미나가 다하면 런이 끝나는 루프에서 "한 번만 더"가 나오는가.

## 2. 화면 흐름

```
런 화면 → (스태미나 0) → 결과 화면 → 상점 → 런 화면 → ...
```

타이틀 화면 없음. 결과와 상점은 한 화면에 합쳐도 된다.

## 3. 런 화면

### 먼지
- 작은 원(2~3px), 흰색에서 연한 파랑. 스프라이트 없이 기본 도형.
- 런 시작 시 `dust_initial`개 배치. 이후 초당 `spawn_rate`개 생성. 화면 상한 `dust_cap`.
- 생성 위치는 화면 안 임의. 단, 커서 반경 안에는 생성하지 않는다.
- 표류: 임의 방향으로 `drift_speed`. 방향에 약한 노이즈. 화면 경계에서 방향 반전.

### 홀드와 중력
- 마우스 왼쪽 버튼 홀드. 커서 위치가 중력원이고 커서를 따라 움직인다.
- `gravity_radius` 안의 먼지는 커서 방향으로 `pull_accel` 가속. 최대 속도 `dust_max_speed`.
- `capture_radius` 안에 들어온 먼지는 제거되고 `mass += dust_mass`.
- 커서 주위에 반경 원과 질량 게이지를 그린다. 게이지는 현재 목표 티어의 임계 대비 비율.

### 행성 생성 (핵심 규칙)
- **홀드를 놓는 순간 행성이 생성된다.** 티어 = `mass`가 넘은 임계 중 가장 높은 해금 티어.
- `mass`가 해금된 최고 티어의 임계에 닿으면 놓지 않아도 즉시 생성된다. 낭비가 없다.
- `mass`가 티어 1 임계 미만이면 행성이 생기지 않고 모은 먼지는 주변으로 흩어져 돌아간다. 손해는 스태미나뿐.
- 생성 즉시 `run_income += 판매가 × sale_mult`. 행성은 원(티어별 크기, 색)으로 1~2초 보이고 사라진다. 이것이 "팔렸다"는 연출이다.
- 생성 후 `mass = 0`.

### 스태미나
- 상단 바. 런 시작 시 `stamina_max`.
- 런 중 항상 `stamina_idle_drain`/초 소모. 홀드 중에는 `stamina_hold_drain`/초 추가 소모.
  - 가만히 있어도 조금씩 닳는 이유: 먼지가 찰 때까지 무한정 기다리는 플레이를 막기 위해서다.
- 0이 되면: 홀드 중이었다면 강제로 놓은 것과 같이 행성을 생성하고, 런을 종료한다.

### HUD
- 좌상: 보유 재화, 런 번호. 우상: 이번 런 수입. 상단 중앙: 스태미나 바.

## 4. 결과 화면

- 이번 런 수입.
- 만든 행성 티어별 개수.
- **지난 런 대비 배율.** `×1.00` 형식. 첫 런은 표시 안 함.
- 최고 런 수입.
- 버튼: 상점으로.

## 5. 상점

- 업그레이드 5개와 행성 해금 2개 (아래 표). 구매 시 재화 차감, 레벨 +1.
- 비용 = `base × growth ^ level`.
- 버튼: 다음 런. 런 사이에만 구매할 수 있다. 런 중 상점 없음.

## 7. 합격 기준

- 3번째 런이 끝났을 때 "한 번만 더"가 나오는가.
- 런 1에서 5까지 결과 화면의 "지난 런 대비"가 매번 1.0을 넘는가.
- 10분 플레이 후에도 홀드가 지루하지 않은가.
- 먼지 1,000개(캡을 올려서)에서 60fps.
- 런 화면 캡처가 스토어 스크린샷의 출발점으로 쓸 만한가. 예쁘지 않아도 "무엇을 하는 게임인지" 보이면 된다.

## 8. 만들지 않을 것

셰이더, 파티클 이펙트, 저장, 로컬라이제이션, 도전과제, 사운드, 타이틀 화면, 티어 4 이상, 특이 천체, 튜토리얼. 5일 안에 위 §3~§5만 만든다.

## 9. 처음부터 지킬 것

[10_Core_Loop.md](10_Core_Loop.md) §8의 요약.

- 숫자는 전부 `double`. 큰 수 라이브러리 없음.
- §6의 값은 데이터 테이블에. 코드 상수 금지.
- 연출 강도 전역 파라미터(0~1)를 만들어 두고, 화면 플래시나 흔들림을 넣게 되면 반드시 곱한다. 프로토타입에서는 쓸 일이 거의 없어도 자리는 잡는다.
- 저장은 안 하지만, 런 사이에 유지되는 상태(재화, 업그레이드 레벨, 해금, 런 통계)를 한 클래스에 모아 둔다. 나중에 그대로 직렬화한다.
- UI 문자열은 한 곳에 모은다.
- 게임 로직은 고정 틱(예: 50Hz). 렌더링만 프레임에 맞춘다.

## 10. 프로토타입이 끝나면 기획 세션에 돌려줄 것

- 런 1~10 각각의 수입과 길이(초).
- 홀드가 지루해진 시점(분). 없었으면 없었다고.
- 스태미나 기본값이 적절했는지. 런이 너무 짧았는지 길었는지.
- 프레임 수치(먼지 300개, 1,000개).
- "놓으면 생성" 규칙이 직관적이었는지.
- 바꾸고 싶어진 수치와 이유.
