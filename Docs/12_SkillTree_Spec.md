# 12. 스킬트리 스펙 (구현 인계)

| 항목 | 값 |
|---|---|
| 상태 | 구조 확정 (S14 채택, 2026-09-18). 수치는 초안 |
| 최종 수정 | 2026-09-18 |
| 대상 | 구현 세션 |
| 1단계 | 데이터 모델 전환. **3주차 첫 작업, 밸런스 작업 전에.** 0.5~1일. 2주차는 평면 상점으로 끝났고 밸런스는 아직 하지 않았으므로 버려지는 것이 없다 |
| 2단계 | 별자리 트리 화면. 1단계 커밋 후. 2~3일 |
| 담당 | 2주차를 만든 구현 세션이 이어서 한다. 자기가 쓴 `Stats`, `Shop`, 검증기, 테스트의 관례를 알고 있다 |

## 1. 목적

평면 상점(스탯당 무한 레벨, 지수 비용)을 노드 그래프로 바꾼다.

- 구매 순서를 설계자가 통제한다. "노드 N개를 산 시점의 전력"이 예측 가능해져 성장세 관리가 쉽다.
- 잠긴 노드가 보이는 것이 "한 런만 더"의 동기가 된다.
- 별자리 형태(점, 선, 글로우)라 아트가 필요 없다.

평면 상점 기준으로 잡은 밸런스는 트리 전환 시 버려진다. 그래서 모델부터 바꾼다.

## 2. 규칙

노드는 두 종류다. **스탯 노드**(스탯 하나를 올린다)와 **관문 노드**(천체 티어를 해금한다).

구매 가능 조건 (전부 만족)
1. `enabled`.
2. `unlockedMaxTier ≥ minTier`.
3. `prereqs` 중 **하나 이상**의 레벨이 1 이상. `prereqs`가 비어 있으면 중심에 인접한 노드로 항상 충족.
4. 레벨 < `maxLevel` (0은 무한).
5. 재화 ≥ 비용. 비용 = `ceil(baseCost × ringCostMult[minTier] × growth ^ level)`.

관문 노드
- 순차. `tier == unlockedMaxTier + 1`일 때만 살 수 있다. 사면 `unlockedMaxTier = tier`.
- 스탯 노드를 요구하지 않는다. 재화만 든다. 저축해서 관문부터 사는 것은 플레이어의 선택이다.

링
- **링 k = `minTier`가 k인 노드들.** 관문 k를 사면 링 k가 열린다. 링 1은 처음부터 열려 있다.
- 환불과 재분배는 없다.

## 3. 데이터 모델

### NodeDef

| 필드 | 타입 | 내용 |
|---|---|---|
| `id` | string | 안정적인 키. 세이브, 로그, 문자열 키에 쓴다. 예: `r1_spawn`, `gate_t2` |
| `kind` | enum | `Stat` / `TierUnlock` |
| `statId` | string | `Stat`일 때. 기존 `UpgradeIds` 그대로 |
| `effectPerLevel` | double | 노드마다 다르다. 뒤 링일수록 크다 |
| `maxLevel` | int | 0 = 무한 (링 11의 엔들리스 노드만) |
| `baseCost`, `growth` | double | 기존과 같은 의미 |
| `tier` | int | `TierUnlock`일 때 해금하는 티어 |
| `minTier` | int | 속한 링. 기존 `revealAtTier`의 일반화 |
| `prereqs` | string[] | 선행 노드 id. any-of |
| `angleDeg` | float | 배치 각도. 반지름은 `minTier`로 계산 |
| `enabled` | bool | 기존과 같음 |

테이블 에셋에 `ringCostMult` (double[], 인덱스 = 링)를 둔다. 기본값 전부 1. **링 하나의 빠르기를 숫자 하나로 조정하는 손잡이다** (§7).

### 스탯 합산

| statId | 합산 | 유효 값 |
|---|---|---|
| `spawn_rate`, `stamina_max`, `dust_cap`, `start_bonus` | 같은 statId 노드의 `effect × level` 합 | 기본값 + 합 |
| `pull_accel`, `sale_mult`, `gravity_radius` | 합 | 기본값 × (1 + 합) |
| `threshold_mult`, `stamina_drain` | 합 (상한 0.9) | 기본값 × (1 − 합) |
| `dust_mass` | 같은 statId 노드의 `effect ^ level` **곱** | 기본값 × 곱 |

### 기존 코드와의 대응

| 기존 | 변경 |
|---|---|
| `UpgradeDef` (스탯당 1행, 무한 레벨) | `NodeDef` (노드당 1행) |
| `revealAtTier` | `minTier` + `prereqs` |
| `UnlockDef` 목록 | `kind = TierUnlock` 노드. 비용은 현재 값 유지 (티어 2만 50 → 30, 티어 3만 400 → 300) |
| `Stats.Add(id)` | 같은 `statId` 노드 전부 합산 |
| `Stats.Compound(dust_mass)` | 같은 `statId` 노드 전부 곱 |
| `MetaState.upgradeLevels` (id → level) | **구조 그대로.** 키만 노드 id |
| `Shop.IsVisible` | `IsAvailable` (§2) + 표시 상태 (§4) |
| `RunRecord.startLevels` | 노드 id 기준. `run_log.csv`는 노드 레벨 대신 **런 시작 시 유효 스탯 값**을 기록 (밸런스에 더 쓸모 있다) |
| 세이브 | 버전 2. `SaveMigration`의 첫 단계가 된다. v1 세이브는 새 게임으로 바꾼다 (통계 포함 초기화, 설정 파일은 유지). 개발 중 세이브뿐이다 |
| 관문과 `unlockedMaxTier` | **단일 진실은 관문 노드의 레벨이다.** 관문을 사면 노드 레벨 1. `unlockedMaxTier`는 로드 시 "연속으로 보유한 관문 수 + 1"로 다시 계산한다. F6(무료 해금)도 관문 노드 레벨을 올린다 |
| `enabled = false` | 없는 노드로 취급한다 (구매 불가, 이미 산 레벨도 효과 0). 밸런스용 스위치이지 플레이어 기능이 아니다. 끈 노드가 다른 노드의 유일한 prereq이면 검증기가 경고한다 |
| 시드 코드 | 노드 테이블도 2주차 방식 그대로: 시드 코드가 에셋에 없는 항목만 채우고, 검증기가 에셋과 시드의 차이를 경고한다 |
| `DataValidator` | 기존 검사 + id 중복, 없는 prereq, 순환, 중심에서 도달 불가능한 노드, 관문 티어 불연속, 모르는 statId, 같은 링에서 각도 겹침 |
| 테스트 | `StatsTests`, `ShopTests`, `DataTests`를 노드 기준으로 교체. `SaveTests`에 v1 → v2 추가. `FmtTests`는 그대로 |
| 오토플레이 봇 | 후보 = 구매 가능한 노드. 정책 옵션 추가: 다음 관문이 "보유 재화 + 지난 런 수입" 이하면 이번엔 사지 않고 저축. 1주차 보고의 "싼 것만 사다 해금을 못 함"을 고친다 |

### 이름

노드 이름을 하나씩 짓지 않는다. `스탯 이름 + 로마 숫자`로 자동 생성한다 (먼지 생성 I, II, III). 관문은 천체 이름.

## 4. 노드 상태

| 상태 | 조건 | 표시 |
|---|---|---|
| 숨김 | `minTier > unlockedMaxTier + 1` | 그리지 않는다 |
| 잠김 | 다음 링이거나 prereq 미충족 | 흐린 점. 이름, 효과, 비용은 **보여준다** (다음 목표) |
| 구매 가능 | §2 조건 1~4 충족 | 재화가 되면 밝게 맥동. 모자라면 고정 밝기 + 비용 붉은색 |
| 보유 | 레벨 ≥ 1, 미완 | 밝은 별. `2/3` 표기 |
| 완료 | 최대 레벨 | 가장 밝은 별. 선이 빛난다 |

## 5. 배치

- 극좌표. 반지름 = `R0 + minTier × dR`. 각도 = `angleDeg`.
- 중심은 시작 노드 "성운". 처음부터 보유.
- 6개 축, 60° 간격.

| 축 | 각도 | 스탯 |
|---|---|---|
| 천체 (관문) | 90° (위) | 티어 2~11 해금 |
| 먼지 | 30° | spawn_rate, dust_cap, start_bonus |
| 중력 | 330° | pull_accel, gravity_radius |
| 판매 | 270° | sale_mult |
| 스태미나 | 210° | stamina_max, stamina_drain |
| 행성 | 150° | threshold_mult, 이후 특이 천체 확률(S9 채택 시) |

- 먼지 질량(`dust_mass`)은 먼지 축과 천체 축 사이 60°에 따로 둔다. 후반 주력이라 눈에 띄어야 한다.
- 같은 링, 같은 축에 노드가 둘이면 ±10°.
- 링 원을 흐리게 그린다. 관문을 사면 그 링 원이 밝아진다.

## 6. 노드 초안

### 기준 수입 I_k

`I_k` = 링 k에 막 진입했을 때의 평균 런 수입. 봇 3런 평균으로 **실측한다.** 초안은 `I_1 = 12` (1주차 실측), `I_(k+1) = 8 × I_k` (현재 해금 비용의 증가율과 같다).

| 항목 | 비용 |
|---|---|
| 일반 노드 1레벨 | 0.4 × I_k, growth 1.5 |
| 먼지 질량 노드 1레벨 | 1.1 × I_k, growth 1.8 |
| 다음 관문 | 약 3 × I_k (현재 해금 비용과 거의 일치) |
| 링 전체 | 약 9 × I_k. 링 안에서 수입이 오르므로 **링 하나에 4~6런** |

| `r1_pull` | 중력 | pull_accel +20% | 2 | 5 | 1.5 | - |

전부 사면: 먼지 생성 66/초, 상한 3,700, 스태미나 390에 소모 −40%(런 약 9분), 판매 ×24, 먼지 질량 약 ×440. 먼지 질량이 링마다 ×2.25 오르는 것은 티어당 필요 질량 ×2.5~3을 상쇄해 **행성 하나당 홀드 시간을 3~6초로 유지**하기 위해서다.

합계: 스탯 노드 약 50개, 관문 10개, 엔들리스 3개. 구매 약 110회, 50런이면 런당 2회.

## 7. 밸런스 절차 (성장세 관리)

1. 봇으로 링 k 진입 직후 3런 평균 수입을 재서 `I_k`를 실측한다.
2. 링 k 노드의 `baseCost`를 §6 공식으로 다시 계산한다.
3. 봇으로 링 k를 통과하는 데 걸린 런 수를 잰다. 목표 4~6런.
4. 벗어나면 개별 노드를 만지지 말고 **`ringCostMult[k]` 하나만** 조정한다.
5. 링 1부터 순서대로. 앞 링이 바뀌면 뒤 링의 `I_k`가 바뀐다.

수입이 링마다 ×8보다 빨리 오를 가능성이 높다(티어 가치 ×3, 질량 ×2.25, 판매 ×1.5가 곱해진다). 그래서 `I_k`는 가정하지 말고 잰다.

## 8. 1단계 범위 (3주차 첫 작업)

시작 전에
- **2주차 작업을 먼저 커밋한다.** 지금 작업 트리에 수정 파일이 20개 넘게 커밋되지 않은 채 있다. 전환이 꼬였을 때 돌아갈 지점이 필요하다.
- 전환은 브랜치에서 한다. 1단계가 합격 기준을 통과하면 커밋하고 2단계로 간다.

만들 것
- `NodeDef`, 테이블 에셋, `ringCostMult`, 합산 규칙, 구매 규칙, 검증기, 세이브 버전 2.
- 링 1~3 노드를 §6대로 입력. 링 4~11은 틀대로 입력하되 수치는 공식값.
- **화면은 기존 2단 목록을 그대로 쓴다.** 오른쪽 목록에 구매 가능한 노드만 비용 오름차순으로, 마지막 행에 다음 관문. 11행을 넘으면 싼 것부터 11행. 잠긴 노드는 트리 화면에서 보여준다.
- 봇 후보와 저축 정책, 로그 열 변경 (헤더가 바뀌면 기존 로그는 자동으로 옮겨진다).
- §10의 규칙 변경 6건.

합격 기준
- 봇 20런 안에 링 3 진입.
- 링 1, 2 각각 4~6런.
- "지난 런 대비"가 1.0 미만인 런이 20런 중 3회 이하.
- 검증기 통과.

## 9. 2단계 범위 (3주차): 트리 화면

- 검정에 가까운 배경, 별 노이즈. 노드는 빛나는 점(관문은 크게), 간선은 가는 선. 보유한 노드 사이의 선은 밝다.
- 조작: 클릭 = 1레벨 구매. 누르고 있으면 반복 구매. 드래그 이동, 휠 확대. 호버 툴팁(이름, 효과, 레벨, 비용).
- 화면을 열면 카메라가 최전선(구매 가능한 노드들의 중심)으로 자동 이동한다.
- 재화는 상단 고정. **"다음 런" 버튼과 Space는 항상 동작.**
- 흐름: 결과 화면([13](13_Result_SolarSystem_Spec.md)) → Space → 트리 → Space → 다음 런. 아무것도 안 사면 3초 안에 다음 런.
- 구매 시 짧은 빛 번짐. `effectIntensity`를 곱한다.

합격 기준
- 처음 보는 사람이 설명 없이 노드를 사고 다음 런으로 간다.

## 10. 2주차 보고 §3에 대한 답 (1단계와 함께 반영)

[Reports/Week2.md](Reports/Week2.md) §3의 질문 9개에 대한 기획 세션의 결정. 트리 전환과 얽힌 것이 많아 여기 모았다.

| # | 질문 | 결정 | 이유 |
|---|---|---|---|
| 1 | 제안 업그레이드 5개의 채택과 공개 시점 | **5개 전부 채택.** 공개 시점은 `revealAtTier`가 아니라 링 배치로 정한다 (§6). 화면 상한과 중력 반경이 링 2, 시작 보너스와 소모 감소와 먼지 질량이 링 3 | "먼지 폭증" 순간이 링 2~3에 온다. 트리가 이 질문 자체를 없앤다 |
| 2 | 질량 초과분 | **최고 해금 티어로 생성할 때 개수 = `floor(질량 / 임계)`.** 나머지는 버린다. 수입은 개수만큼. 화면에는 행성 하나 + `×N` 표기 | 트리에서는 먼지 질량 노드가 링에 묶여 있어 정상 진행 중에는 먼지 1개가 임계의 4% 이하다. 문제가 되는 곳은 엔들리스(무한 질량 노드)뿐이고, 이 규칙이면 질량이 계속 수입으로 이어진다. 하위 티어에서 놓을 때의 초과분은 지금처럼 버린다. 임계에 맞춰 놓는 것이 손맛이다 |
| 3 | "지난 런 대비"에 quit, crash 런 포함 여부 | **제외.** 비교 대상은 가장 최근의 스태미나 종료 런. quit, crash 런은 기록하되 배율과 최고 기록에서 뺀다 | 10초 만에 끈 런이 다음 런의 배율을 튀게 한다 |
| 4 | quit 때 홀드 중이던 질량 | **강제 생성한다.** 스태미나 종료와 같게. crash는 불가능하므로 그대로 버린다 | 플레이어가 정상 종료로 손해를 보면 안 된다 |
| 5 | `enabled = false`의 의미 | **지금대로.** 효과까지 끈다. §3 표 참고 | 밸런스용 스위치다 |
| 6 | 큰 배율 표시 | **×1,000 미만은 `×1.00` 형식, 그 이상은 `Fmt.Num` 표기 (`×347M`)** | 해금 런에서 큰 값이 나올 수 있다 |
| 7 | 숫자 표기 세부 | **접미사 목록과 뒷자리 0 유지(1.00K) 그대로** | 폭이 일정해야 카운트업 때 숫자가 흔들리지 않는다 |
| 8 | 해금 행의 판매가 표시 | **유지.** 트리에서는 관문 노드 툴팁에 "티어 5 · 판매가 2.00K · 필요 질량 400" | 관문을 살 이유가 숫자로 보인다 |
| 9 | 재화가 소수로 쌓임 | ~~판매 시 올림.~~ **[14](14_Planet_Visual_Spec.md) §8로 대체: 런 종료 시 1회 올림.** 아래는 원래 결정. **판매 시 올림.** 행성 하나의 수입 = `ceil(판매가 × 판매 배율)`. 재화는 항상 정수 | "1.75가 1로 보임" 문제가 사라진다. 올림이라 플레이어에게 유리한 쪽이다 |

2주차 보고 §5의 알려진 문제 중 기획이 답할 것
