| 항목 | 값 |

## 1. 현재 위치

- 1~5주차 묶음이 사흘 만에 끝났다(9/17~9/19). 게임은 처음부터 엔딩, 엔들리스까지 이어진다.
- 5주차는 `ending` 브랜치에 있고 main에 병합되지 않았다. 다음 작업 프롬프트의 첫 단계에서 병합한다.
- 봇 완주 결과: **엔딩까지 31런, 게임 시간 50분.** 링 1~4는 5~6런씩으로 목표 안이지만, 링 5~11은 3·2·1·1·1·1·1런으로 무너진다. 먼지 질량 복리가 주원인이다.
- 설계 목표는 40~70런, 2~4시간이다. **남은 일 중 가장 큰 것은 후반 밸런스다.**
- 밸런스 데이터는 아직 전부 봇 기준이다. 사람 플레이 기록이 없다 (R15).

**이 속도에서는 개발이 아니라 Steam 쪽 시계가 병목이다.**

| Steam 쪽 제약 | 기간 |
|---|---|
| 앱 수수료를 낸 날부터 출시 가능일까지 | 최소 30일 |
| "출시 예정" 스토어 페이지 공개 기간 | 최소 2주. 찜을 모으려면 4~8주 |
| 스토어 페이지 검토 | 3~5영업일 |
| 빌드 검토 | 수일 |
| 2026년 10월 Next Fest (10/19~10/26) | 등록 마감 8/31. **이미 지났다** |
| 2027년 2월 Next Fest (2/22~3/1) | 등록 마감 2027-01-10, 데모 빌드 1/25, 전체 항목 2/8 |
| 겨울 세일 | 2026-12-17 ~ 2027-01-04. 이 기간 출시는 피한다 |

## 2. 출시일 선택 (D12, 개발자 결정)

| | A안: 11월 중순 출시 | B안: 2월 Next Fest 후 3월 출시 |
|---|---|---|
| 출시일 | **2026-11-17 (화)** 제안 | 2027년 3월 중순 |
| 찜 모으는 기간 | 약 5주 | 약 5개월 + Next Fest |
| 데모 | 선택 | 필수 |
| 장점 | 빠르다. 완성된 게임을 넉 달 묵히지 않는다. 첫 출시 경험을 바로 얻는다 | 이 장르에서 가장 효과적인 찜 확보 수단을 쓴다. 판매량이 더 기대된다 |
| 단점 | 찜이 적어 출시 첫 주 노출이 약하다 | 개발이 끝난 뒤 넉 달을 기다린다. 그 사이 범위가 늘어나기 쉽다 |

**추천: A안.** 개발자가 처음부터 "빨리"를 우선했고, 게임 규모가 작으며, 첫 출시 경험 자체가 목표다. 판매를 우선하면 B안이다.

두 안은 앞으로 3주가 같다. 결정은 8주차(스토어 자산, 데모) 시작 전인 **10월 9일까지** 하면 된다.

## 4. 개발 작업 목록

### 4.1 6주차: 손맛과 다양성, 밸런스

**스펙은 [20_Week6_Spec.md](20_Week6_Spec.md), 프롬프트는 [Prompts/Week6_Prompt.md](Prompts/Week6_Prompt.md).** 1차 점검 피드백으로 범위가 커졌다. 항목과 순서는 20 §2. 약 7일이고, 기존 2~3일에서 4일 늘었다. 개발 트랙에 여유가 있어 11/17 출시는 유지된다.

- A 즉시 수정 3건(스태미나 소모, 천체 잔류 시간, 혜성 꼬리). 프롬프트 [Prompts/QuickFix_1.md](Prompts/QuickFix_1.md)
- B 먼지 흡인 보정(경계 감쇠, 접선 감쇠, 통과 방지)
- C1 먼지 종류(트리 해금 + 확률 노드, 먼지 질량 복리 노드를 대체), C2 파편 시스템(트리 노드 6개)과 가격 곡선 완화([19](19_LowTier_Options.md)), C3 특수 능력(착수 직전에 구체안)
- 가격 곡선 완화는 링 비용 재조정과 반드시 한 묶음으로 처리한다 (R21)
- D 홀드 중 중력원 추종 속도 제한 실험
- 그다음이 아래 밸런스다. 위 변경이 전부 경제에 영향을 주므로 순서를 바꾸지 않는다.

선행 조건: 사람 플레이 기록, S9와 S16 결정. 기록이 없으면 봇만으로 진행하되 목표를 보수적으로 잡고 외부 테스트에서 확인한다.

- **후반 붕괴 해결.** 링 5 스냅샷부터 링별로 다시 잰다. 목표는 봇 기준 링 5~10 각 3~5런, 엔딩까지 40런 이상, 70~90분. 사람 기록이 오면 분 단위 목표를 사람 기준으로 바꾼다.
  - 수단은 링별 비용 배율 상향, 먼지 질량 노드 약화(×1.5 → ×1.3 등), 관문 비용 상향. 어느 조합이 나은지는 측정으로 고른다.
- 행성 하나당 홀드 시간이 링 3~9에서 7~8.6초로 목표(3~6초)보다 길다. 사람 플레이로 체감을 확인하고 목표 자체를 다시 본다.
- 5주차 보고의 엔딩 관련 수정 2건 (§8).
- S9(특이 천체), S16(완성도 보너스) 채택 시 구현과 밸런스 반영.
- 섬광 가장자리를 더 어둡게 (§8).

### 4.3 8주차: 스토어 자산, 데모

- 캡처 도구(S4): 결과 태양계를 고해상도로 찍고 제목을 얹는다. 캡슐 규격 7종은 03 §2.
- 스크린샷 5장 이상: 런 화면, 태양계 초반과 후반, 별자리 트리, 항성 점화, 초신성.
- 트레일러 30~60초: 엔딩 재생 키와 봇으로 장면을 뽑는다.
- 데모(B안이면 필수, A안이면 선택): 링 4 진입까지, 마지막에 찜 안내.

### 4.4 9주차: 외부 테스트와 출시 후보

- 테스터 3~5명. 세이브와 런 기록을 받아 링별 시간과 이탈 지점을 본다.
- 확인할 것: 첫 5분에 조작을 이해하는가, 엔딩까지 몇 시간인가, 지루한 구간은 어디인가.
- 이후 버그 수정과 수치 조정만 한다. 새 기능은 넣지 않는다.

## 7. 새로 발견한 공백

지금까지의 계획 어디에도 없었지만 출시에 필요한 것이다. 전부 §4.2에 넣었다.

- **사운드가 없다.** 매 주차 "만들지 않을 것"에 있었다. 소리 없는 Steam 게임은 리뷰에서 바로 지적된다.
- **게임을 끝낼 방법이 없다.** Esc 메뉴가 없다.
- **첫 실행 안내가 없다.** 홀드라는 조작을 설명 없이 알아채야 한다.
- **폰트를 윈도우에서 빌려 쓴다.** 리눅스와 스팀 덱에서 한글이 깨질 수 있다.
- **세이브 폴더가 제품명과 회사명에 묶여 있다.** 지금은 `DefaultCompany\Incremental`이다. 이름을 바꾸면 기존 세이브를 못 찾는다.
- **성능은 전부 에디터 수치다.** 빌드에서 잰 적이 없다.
