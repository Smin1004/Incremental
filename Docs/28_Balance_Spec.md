## 2. 시간제 판 (스태미나 → 시간) — 11차

**개발자 (10/14):** "스태미나보다 N초 동안 움직일 수 있게 하는 편이 낫다. 직관적이고, 시간으로 가는 게 관리하기 편하다."

| 지금 | 바뀐 뒤 |
|---|---|
| 스태미나 최대치. 홀드하면 1.5/초, 가만히 있으면 0.3/초 줄어든다 | **판 시간 N초.** 홀드 여부와 상관없이 1초에 1씩 줄어든다. 0이면 판이 끝난다 |
| `stamina_max` 노드 (최대치 +) | **`run_time` 노드 (+초).** 노드 id(세이브 키)는 그대로 두고 스탯만 바꾼다 |
| `stamina_drain` 노드 (소모 −) | **`run_time` 노드로 합친다** (+초). 관리할 축을 하나로 |
| HUD 위쪽 스태미나 막대 "스태미나 182 / 182" | **시간 막대 "남은 시간 23초"** (같은 자리, 같은 스타일) |
| `F10` 소모 프리셋, `G` 고리 게이지 모드, `L` 스태미나 성장 배율, `staminaNodeScale`, 소모 감소 상한(`maxReduction`의 소모 쪽) | **지운다** |
| `Home` 스태미나 즉시 소진 | 남은 시간 0 (같은 키) |

- **시작값(임시):** 기본 판 시간 `runTimeSec` **30초**. 노드 합계는 링 10까지 사면 **+90초**(링 11 판 약 120초). 링별 배분은 §3의 판 길이 열을 따른다. 정확한 값은 밸런스 패스에서 정한다.
- 홀드에 비용이 없어진다. 판 내내 누르고 있는 것이 최선이 된다. 이 게임에서는 자연스럽다고 본다(능력 충전도 홀드 중에만 찬다). 손목 대책은 홀드 토글(§2.1)이다.
- 런 로그(`run_log.csv`)의 스태미나 열은 판 시간 열로 바꾼다. 세이브 마이그레이션은 버전을 올려 처리한다(진행 중이던 판은 지금 규칙대로 끝난 것으로).

### 2.1 홀드 토글 — 11차

- 설정 `holdToggle` (`settings.json`, 기본 끔). 켜면 **클릭 한 번 = 누르기 시작, 다시 클릭 = 놓기.** 판이 끝나면 놓은 상태로.
- 옵션 화면이 아직 없으므로 디버그 키 `H`로 켜고 끈다(토스트). 출시 기능의 옵션 화면에 같은 설정으로 올린다.

- 봇은 사람보다 빠르다. 밸런스 패스에서 봇 시간을 사람 시간으로 바꾸는 비율은 §4의 측정 플레이로 정한다. 그 전에는 1주차 비율(사람이 봇보다 3~4배 길다)을 쓰지 않는다. 그때와 조작이 다르다. **봇은 이 표의 판 수만 맞추고, 시간은 측정 플레이로 확인한다.**

## 4. 개발자 측정 플레이 시트 (밸런스 패스 뒤)

**언제:** 밸런스 패스가 끝난 빌드(또는 에디터)로.
**어떻게:** `Shift+F9`(새 게임)부터 **40분** 플레이한다. 평소처럼 하면 된다. 디버그 키는 쓰지 않는다.
**기록:** 11차가 만드는 진행 로그(`progress.csv`와 콘솔 `[Progress]`)가 관문 구매 시각과 판 번호를 자동으로 남긴다. 따로 적을 것은 아래 "느낌" 칸뿐이다.

| 시점 | 목표 | 실제 (자동 기록) | 느낌 (직접, 한 줄) |
|---|---|---|---|
| 첫 판 끝 | 30초 | | 무엇을 해야 하는지 알았나 |
| 첫 구매 | 1분 안 | | |
| 링 2 관문 | 4:00 (±1분) | | 첫 5분이 빨랐나 |
| 링 3 관문 | 9:30 | | |
| 링 4 관문 (수축) | 15:30 | | |
| 링 5 관문 | 23:00 | | |
| 링 6 관문 (궤도석) | 31:00 | | |
| 40분 지점 | 링 7 도착 근처 | | 지루했던 구간, 기다린 구간 |

- **통과 기준:** 관문 도착이 목표의 ±25% 안. 벗어나면 그 링의 비용을 고친다.
- 사람/봇 비율 = 이 기록 ÷ 같은 링의 봇 시간. 이 비율로 링 7~11을 예측한다(40분 뒤는 재지 않는다).
- 40분 뒤의 후반은 밸런스 패스의 봇 측정과 링 시작 스냅샷으로 따로 본다.

## 5. 트리 재구성 (개발자 의견 대기)

**개발자 (10/14):** "스킬트리를 좀 더 세분화하고, 카테고리별로 나누기 위해 업그레이드 사항들을 조정하려 한다."

밸런스 패스 프롬프트는 이 의견을 받은 뒤 쓴다. 기획 세션이 미리 정리한 재료:

- 지금 축 7개: 먼지(30°), 질량(60°), 파편(140°), 행성(150°), 시간(옛 스태미나, 210°), 능력(240°), 추종·중력(320°·330°). 노드 92개.
- 강화 레벨 세분화(C3-6): 능력 강화 3레벨 → 5~6레벨, 한 레벨 효과는 절반.
- `gravityGrowthScale` 0.7을 반경 노드 값에 직접 반영한다(툴팁이 실제와 같아진다).
- 고를 거리: 카테고리 이름과 개수, 링마다 열리는 노드 수, 갈림길(택일 노드)을 둘지 (R14).

## 6. 밸런스 패스 순서 (§5 뒤에 프롬프트로)

1. 트리 재구성을 시드에 반영한다. **링 시작 스냅샷을 다시 만든다** (재구성된 트리 기준).
2. 봇(결정을 쫓는 판, 11차)으로 링별 처리량 I_k를 다시 잰다.
3. §3 표의 판 수에 맞춰 링 비용을 다시 만든다. 판 길이 노드를 §3의 열에 맞춘다.
4. 궤도석(포획 ×2.2, 24 §24.4), 먼지 보충 가속, 증폭 결정의 몫을 확인한다.
5. 엔들리스: 링 11 끝없는 노드로 봇 100판 상당을 돌린다. 수가 무한대에 닿는지 본다.
6. 바꿀 때마다 빌드에서 합성 최악 장면을 다시 잰다 (R28).
7. 보고서: 링별 판 수·봇 시간 표, 바꾼 값, **결정 요약 표**.
