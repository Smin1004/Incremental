## 1. 한 줄 정의

우주를 떠도는 먼지를 **홀드로 만든 중력**으로 끌어모아 행성을 만들고 판다. 스태미나가 다하면 런이 끝나고, 업그레이드해서 다음 런에 더 큰 행성을 만든다. 외부 아트 없이 파티클과 수식만으로 성장을 보여주는 **짧은 능동형 증분(incremental) 게임.** 1인 개발, Steam 출시.

## 2. 확정 사항

- 장르: 짧은 능동형 증분. 완전 방치형이 아니다
- 레퍼런스: Bills Must Be Paid(런 기반), You Know The Drill. 그 외 증분 게임 전반
- 플랫폼: PC, Steam. Windows 우선
- 개발: 1인, 속도 우선
- 그래픽: 외부 아트에 의존하지 않는다. 파티클과 수식 기반 절차적 비주얼이 핵심 표현이다
- 엔진: Unity 6000.0.66f2, 2D URP, Input System
- 테마: 우주. 먼지 → 중력 → 행성 (D1)
- 핵심 반복 행동: 마우스 홀드로 중력 생성. 먼지를 끌어모아 행성을 만들고 판매 (D2)
- **구조: 런 기반. 홀드가 스태미나를 소모하고, 소진되면 런 종료 → 결과 화면 → 스킬트리 → 다음 런** (E7)
- **성장 시스템: 스킬트리.** 별자리 형태. 티어 해금 관문이 링의 경계가 된다 (S14, 2026-09-18)
- **결과 화면: 태양계.** 이번 런에 만든 행성들이 보여주기용 중심 항성을 공전한다. 런 중 생성된 행성은 그 궤도로 떠난다 (S13, 2026-09-18)
- 엔딩: 있음 + 엔들리스 (D4)
- 업그레이드 축: 먼지 생성 빈도, 필요 먼지 수, 모으는 힘, 판매 비용, 행성 해금, 스태미나
- 플레이 경험: 플레이 타임은 길지 않다. 매 런의 결과 화면과 항성 점화, 초신성에서 "폭발적 성장"을 체감시킨다

핵심 루프 상세는 [10_Core_Loop.md](10_Core_Loop.md). **출시까지의 일정과 남은 일은 [16_Release_Roadmap.md](16_Release_Roadmap.md).** 11~15는 구현 완료. 다음 인계 문서(6주차 밸런스)는 사람 플레이 기록과 S9, S16 결정 뒤에 쓴다.

## 6. 설계 원칙

1. **숫자가 곧 그림.** 모든 자원과 배율은 화면의 무언가에 직접 대응한다.
2. **런은 플레이, 스킬트리는 결정.** 런 중에는 홀드만 한다. 업그레이드는 런 사이에.
3. **결과 화면이 성장 그래프다.** "지난 런 대비 ×N"이 매 런 1.0을 넘는다.
4. **데이터 주도.** 밸런스 값은 코드가 아니라 데이터 테이블에 둔다.
5. **만들지 않는 것.** 스토리, 캐릭터, 손그림 아트, 멀티플레이, 모바일, 오프라인 진행, 큰 수 라이브러리, 프레스티지, 먼지 종류, 런 중 상점.

- 먼지 성능은 1주차에 확인됐다(1,000개에서 틱 0.25ms). 원래 3주차에 있던 성능 작업은 뺐다.

- **이 속도라면 개발보다 Steam 쪽이 병목이다.** 파트너 가입과 세금, 은행 정보에 수일, 스토어 페이지 검토에 3~5영업일이 걸리고, 찜을 모으려면 페이지가 출시 4~8주 전에 떠 있어야 한다. 파트너 가입은 지금 시작하는 것을 권한다 (03 §1). 스토어 페이지에는 이름(D7)이 필요하다.
- 8주를 지켜야 하면 7주차와 8주차를 합치고 데모를 포기한다. 권하지 않는다. 이 장르에서 데모는 관례다.
- 스토어 페이지는 출시 최소 2주 전에 공개되어야 한다. 7주차에 초안을 올린다 (03 참고).
